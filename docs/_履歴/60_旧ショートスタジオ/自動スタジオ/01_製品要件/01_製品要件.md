# Shorts Auto Studio Product Requirements

## 目的

すーすーわーわーキャラを使い、YourTIME向けの健康・口腔育成・未病・親子コンテンツを半自動で量産する。単なる動画編集ツールではなく、プロのコンテンツ設計・健康コミュニケーション・キャラ人格・マーケティング・心理設計を内蔵した「ショート動画生成プロダクト」として扱う。

## どちらがよいか

現状の `JSON + render.py` はMVPの中核として残すべき。理由は、構造化されていて自動生成と相性がよく、Git管理・プレビュー・レンダリングがすでに動くため。

ただし、最終形を「JSON手編集」にしてはいけない。JSONは内部形式にし、ユーザーはWeb UIで以下だけ触る。

- ネタ/テーマ
- 1人/2人
- 使用キャラ
- タイトル微修正
- セリフ微修正
- キャラ位置・セリフ位置・サイズ
- 承認/却下/フィードバック

キャラは、表示用画像が存在する全キャラを選択可能にする。特徴説明が未整備のキャラは `詳細未設定` として扱い、後からキャラ台帳を拡張する。

推奨方式は `生成AI + テンプレート変数 + キャラ台帳 + ルール/フィードバック記憶 + Web編集UI + Pythonレンダラ`。

## ユーザーストーリー

- YourTIME運営者として、1日2-3本の投稿候補を短時間で確認し、承認したい。
- 健康・歯科スタッフとして、専門情報を親子にも伝わる言葉へ自動変換したい。
- 非エンジニアの制作担当として、キャラらしさを壊さずにタイトル・セリフ・位置だけ直したい。
- マーケ担当として、投稿後にどの型がよかったかを次回生成に反映したい。
- 管理者として、医療断定・不安煽り・キャラ崩れを避けた安全な動画だけを出したい。

## 対象ユーザー

### 運用者

- YourTIME運営者
- イベント/広報担当
- 歯科・健康関連スタッフ
- コンテンツ制作担当

### 視聴者

- なんとなく体に不調を感じている人
- 健康について正しく知りたい人
- 親子で楽しく健康になりたい人
- 医療従事者・専門職・出展者

1本の動画で全員に話しかけない。主ターゲットは必ず1つに絞る。

## MVP

MVPは「半自動生成 -> プレビュー -> 軽微修正 -> 承認 -> MP4出力」まで。

投稿API連携は初期スコープ外。まずは、毎日2-3本のショート候補を安全にMP4化し、人間が各SNSへ投稿できる状態を作る。

画像生成機能は初期スコープ外。API課金を避けるため、既存キャラ画像・既存背景・ローカルレンダー演出を使う。

2026-06-26時点では、Web UIからローカル開発用Vite middlewareを経由してPythonレンダラを起動できる。現在のMVPは、Web UIでrender.py互換JSONを生成し、`/api/shorts-studio/render` が `shorts/render.py --check` と `shorts/render.py` を実行し、MP4の `downloadUrl` を返す。JSONダウンロードとCLIコマンドコピーは保険導線として残す。

### 画面を開いてからMP4出力まで

```text
1. 今日の運用ダッシュボードを開く
   - 今日の必要本数、未生成、レビュー待ち、MP4出力済みを確認する

2. 投稿枠を選ぶ
   - 朝/昼/夜などの枠、主ターゲット、テーマ、投稿目的を確認する

3. 候補を生成する
   - 1人/2人、キャラ、タイトル、脚本、演出、layout、投稿文下書きを生成する

4. 候補を選ぶ
   - 伸び予測、ターゲット適合、YourTIMEらしさ、医療表現リスクを見て採用案を選ぶ

5. レビューする
   - タイトル、セリフ、キャラ左右、上下位置、演出、尺を微調整する

6. 高速プレビューを見る
   - 1:1安全域、冒頭挨拶、天気、字幕読みやすさを確認する

7. MP4を生成する
   - 開発サーバでは `MP4を生成` ボタンで `--check` 検証後にMP4を生成する
   - 本番/previewで実行ブリッジがない場合は、render.py互換JSONとCLIコマンドの半自動導線を使う

8. 投稿補助を出す
   - キャプション、ハッシュタグ、投稿チェックリストを表示する

9. 人間がSNSへ投稿する
   - 初期は手動投稿。自動投稿は後段の別フェーズ

10. 学習へ反映する
   - 修正理由、却下理由、採用理由を次回生成ルールへ保存する
```

### MVP完了条件

ユーザーが画面を開いてから、次の状態まで迷わず到達できることをMVP完了条件にする。

- 今日必要な投稿枠が見える
- 1つの投稿枠を選べる
- 候補を生成できる
- 候補の採用/保留/却下を選べる
- タイトル、セリフ、キャラ、立ち位置、上下位置、演出、タイトル雰囲気を修正できる
- 高速プレビューで1:1安全域、タイトル位置、キャラ位置、字幕位置を確認できる
- 必須チェックを通過した候補だけMP4生成へ進める
- 現MVPではrender.py互換JSONをダウンロードし、CLIコマンドをコピーできる
- 現MVPでは `shorts/render.py --check` でMP4生成前の失敗要因を分類できる
- Web UI直接生成版では、MP4生成中、成功、失敗が画面で分かる
- Web UI直接生成版では、成功時にMP4をダウンロードできる
- 投稿文、ハッシュタグ、手動投稿チェックリストを確認できる
- ユーザーが `手動投稿済みにする` を押せる
- 修正/採用/却下理由を次回ルールへ送れる

### MVPの非ゴール

次は初期MVPで扱わない。

- SNS APIによる自動投稿
- SNS APIによる予約投稿
- 投稿後の自動実績取得
- 画像生成API連携
- 音声生成API連携
- フレーム単位編集
- 任意プロンプトだけで動画を作る汎用生成
- 医療診断、個別治療助言、効果保証

## ワークフロー仕様

### 全体状態

1本の動画枠は次の状態を持つ。

| 状態 | 意味 | 主ボタン | 次に進む条件 |
| --- | --- | --- | --- |
| `slot_empty` | 投稿枠だけある | `候補を作る` | 投稿枠にターゲット、テーマ、目的がある |
| `generating_plan` | タイトル/脚本/演出案を生成中 | なし | 生成成功 |
| `candidate_ready` | 候補が選べる | `この案でレビュー` | 1案を選択 |
| `reviewing` | 編集中 | `高速プレビュー` | 必須項目が空でない |
| `preview_ready` | PNGプレビュー確認済み | `MP4生成へ` | 品質チェックがすべてOKまたは警告を承認 |
| `render_queued` | MP4生成待ち | `生成を開始` | 内部JSONが生成済み |
| `rendering` | MP4生成中 | なし | render job成功/失敗 |
| `render_failed` | MP4生成失敗 | `再生成` | エラー原因を表示済み |
| `mp4_ready` | MP4出力済み | `MP4をダウンロード` | ファイルURL/パスがある |
| `manual_post_ready` | 手動投稿準備済み | `手動投稿済みにする` | MP4、投稿文、ハッシュタグが表示済み |
| `posted_manually` | 人間がSNSへ投稿済み | `学習へ送る` | 投稿先メモまたは投稿済みチェックあり |
| `learning_review` | 学習反映待ち | `次回ルールに反映` | 採用/却下/修正理由が1つ以上ある |
| `learned` | 学習反映済み | `今日へ戻る` | 学習ルール保存済み |

- 演出

### 必須チェック

MP4生成へ進む前に、次をチェックする。

- 冒頭1行目が `おはようございます！`
- 冒頭2行目が `今日のふわふわランドの天気は、、、`
- 冒頭3行目が `{天気}です！`
- 天気が普通に理解できる
- 尺見込みが30秒以上60秒以内
- タイトル、キャラ、字幕が1:1安全域に入っている
- タイトルが上端に近すぎない
- 字幕が下端に近すぎない
- 主ターゲットが1つだけ設定されている
- 医療診断/効果保証/不安煽りがない
- YourTIMEとの接続が1箇所以上ある
- スマホ視聴だけで終わらず、体操/会話/行動につながる

エラーはMP4生成を止める。警告はユーザーが承認すれば進める。

エラー例:

```text
冒頭の天気ルールが違います。「今日のふわふわランドの天気は、、、」の次に「晴れです！」のように入れてください。
```

警告例:

```text
タイトルが少し上寄りです。生成はできますが、1:1表示で窮屈に見える可能性があります。
```

### MP4生成

MP4生成画面には次を表示する。

- 生成対象タイトル
- 尺
- 解像度
- 出力ファイル名
- レンダリング状態
- 最終チェック結果
- 生成ログのユーザー向け要約

主ボタン。

- `MP4を生成`
- `生成をやり直す`
- `MP4をダウンロード`
- `投稿準備へ`

生成中文言:

```text
MP4を生成しています。画面はこのままでも大丈夫です。
```

成功文言:

```text
MP4ができました。ダウンロードしてSNSへ手動投稿できます。
```

失敗文言:

```text
MP4生成に失敗しました。原因を確認して、もう一度生成してください。
```

失敗時に表示する情報。

- ユーザー向け原因
- 再生成ボタン
- 編集画面へ戻るボタン
- 開発者向け詳細を開くボタン

現MVPの半自動導線では、画面上に次を表示する。

- render.py互換JSONのダウンロード
- コピー可能なCLIコマンド
- 期待される出力先 `shorts/out/*.mp4`
- 実行前検証コマンド `python3 shorts/render.py --check {jsonPath}`
- `--check` 失敗時の分類: `schema_invalid` / `asset_missing` / `layout_out_of_bounds` / `duration_out_of_range` / `unsupported_animation`

Web UIから直接 `shorts/render.py` を起動する機能は、ローカルNode API等の実行ブリッジ承認後に実装する。

### 投稿補助

SNS API連携はしない。画面では手動投稿に必要な情報だけ出す。

- MP4ダウンロード
- 投稿タイトル
- キャプション
- ハッシュタグ
- 投稿先メモ
- 手動投稿チェックリスト

手動投稿チェックリスト。

- MP4をダウンロードした
- 音声/字幕を確認した
- 投稿文を確認した
- 医療表現に問題がない
- 投稿先SNSを選んだ
- SNS側で投稿した

`手動投稿済みにする` は、最低限 `MP4をダウンロードした` がチェック済みで押せる。

### 学習反映

学習画面では、ユーザーの行動を次回ルールに変換する。

保存するもの。

- 採用理由
- 却下理由
- タイトル変更前/変更後
- セリフ変更前/変更後
- レイアウト変更前/変更後
- キャラ変更前/変更後
- 演出変更前/変更後
- `今回だけ` / `次回から反映`

ユーザー向け文言:

```text
今回の直し方を、次の候補づくりに反映します。
```

保存後文言:

```text

```

## プロダクト原則

- 断定より提案
- 恐怖より行動
- 専門性より生活接続
- スマホ滞在より親子の会話/体験
- 完全自動より人間の承認
- 自由編集より安全な型
- 毎回の思いつきより蓄積するルール
