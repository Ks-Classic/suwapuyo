## 3. 感動の核① — 召喚（降臨＋喜び）

> **演出の絵コンテ・タイミングは `05` に詳細。本節は実装契約。**

### 3.1 体験
**自分が描いた絵が、すわぷよ盤面に“生きて”降臨し、自分のプレイに合わせて喜ぶ。**（他人の絵は出さない＝`03`§1.1）

### 3.2 ★降臨（魔法の瞬間①）— 初回のみ特別、2回目以降は短縮
| 局面 | 動き | 時間/イージング | 補助 |
|---|---|---|---|
| 1. 予兆 | 上空に影＋キラ粒子 | 300ms / ease-out | 既存 `spawnParticles` |
| 2. 降下 | 自分の絵が上空からゆっくり降下＋微揺れ | 800ms / cubic ease-out | 透過PNG（§6.5） |
| 3. 着地 | スカッシュ&ストレッチで弾む | 250ms / back ease-out | 着地ポップSE |
| 4. 名乗り | ふきだし「あそぼ！」＋キラ | 600ms→fade | 声なし |
| 5. 常駐 | 待機bob（sin揺れ）ループ | — | §3.4 |
- 2回目以降は1〜4省略→即常駐。初回判定＝`progressStore.first_summoned_at` / buddyStore。

### 3.3 ★喜び（魔法の瞬間②）— 連鎖ほど大喜び・声なし
| トリガー | 動き | 補助 |
|---|---|---|
| ぷよ消し（`popClearable` 完了） | 小ジャンプ（squash→pop 120ms） | — |
| 連鎖2以上 | 大ジャンプ＋スケールpop＋キラ＋ふきだし「すごい！」 | 既存 chain SE（連鎖数比例・上限） |
| 連鎖中の多発 | **1連鎖=大喜び1回にデバウンス** | tween過多/ジャンク防止 |
- 声なし。フック＝`PuyoDemo.popClearable()`（`:838`）末尾 or `onChainChange?`（`:341`）ピークで `cheerBuddy(level)`。盤面ロジック不変。

### 3.4 実装（応援レイヤー）
- `PuyoDemo` に独立 `cheerLayer: Container`（`uiContainer` 同階層、盤面の右 or 上）。
- 相棒スプライト1体：buddyStore（§6.1）Blob→ObjectURL→Texture。`anchor 0.5`、`record.scale` 基準にフィット。
- `destroy()`（`:1208`）で Texture/Container 解放＋**テクスチャ破棄→`revokeObjectURL`順**（リーク回避）。

### 3.5 状態
| 状態 | 表示 |
|---|---|
| 相棒あり・初回 | 降臨フル → 常駐 |
| 相棒あり・2回目以降 | 即 常駐bob |
| 相棒なし | 既定相棒（例 すーすー）・降臨なし |
| 画像ロード失敗 | 既定相棒へフォールバック＋`console.debug`（track()ではない＝§6.3注） |

### 3.6 デモ種（準備）
- 事前に1枚の透過PNGを buddyStore に仕込む（`source:"demo-seed"`）。会議で描く時間/ネットが無くても②〜成立。

### 3.7 受け入れ基準（感動ビート含む）
1. 相棒ありで `/` 初回 → **降臨演出**が再生される。
2. ぷよ消しで小喜び／**連鎖で大喜び＋SE**。連鎖中に多重発火しない。
3. 2回目`/`は降臨省略。相棒なしでも正常プレイ。
4. 画面遷移でTexture/ObjectURLリークなし。盤面・連鎖・既存SFX回帰なし。
5. `npm run build` green / `any`なし / lint pass。

## 6. 共通基盤

### 6.1 buddyStore（同一端末・相棒の共有ローカル）= 召喚の心臓
ふわふわランドとすわぷよを密結合させない**中立な共有ストア**。

- 新規 `src/shared/buddyStore.ts`。専用 IndexedDB（`suwapuyo-buddy`/store `current`）に**1件**。画像は**Blob保持**。

```ts
export interface BuddyRecord {
  artworkId: string; label: string;
  image: Blob;            // 透過PNG（§6.5）
  width: number; height: number; scale: number; // 既定 0.6
  source: "fuwafuwa-local" | "demo-seed" | "liff";
  firstSummonedAt?: string; createdAt: string;
}
export async function setBuddy(r: BuddyRecord): Promise<void>;
export async function getBuddy(): Promise<BuddyRecord | null>;
export async function markSummoned(): Promise<void>;
export async function clearBuddy(): Promise<void>;
export function buddyImageObjectUrl(r: BuddyRecord): string;
```
- 書き込み: ふわ描画完了（§6.5）／デモ種（§3.6）。読み込み: すわぷよ mount。**すわぷよは `getBuddy()` のみ**＝本番LIFF差替で無改修。

### 6.2 配信オリジン（地雷・必読）
- 本番は `ふわふわランド旧統合版` **サブドメイン**（`vercel.json`＋`App.tsx` hostname分岐）＝別オリジン＝**IndexedDB非共有**。
- **デモは1オリジンpath配信**（`/`＝すわぷよ、`/fuwafuwa`＝描画）。**hostname分割を避けpath/hashで判定**。これで buddyStore 共有＝同一端末召喚が動く。

### 6.3 計測 track()（既存enum＋metaで吸収・DB変更なし）
- **デモ実体**: 既存 `src/fuwafuwa-land/lib/track.ts` の `track(type, id?, meta?)`（no-op/console）。すわぷよからも同import。
- **DB配線時の写像**（enum外の名前を使わない）:

| やりたい計測 | event_type(enum) | meta |
|---|---|---|
| タップ（大画面/マップ） | `tap` | `{surface, id}` |
| 紹介ポップ開く | `popup_open` | `{surface, id}` |

## 14. 本番化の前方互換シーム（最低限・手戻り防止）

> 原則: **本番化は“足すだけ”**。デモは中身を薄く、**境界（差し替え点）とデータの形だけ本番品質で固定**する。下記を守れば、解放/LIFF/CMS/送客/サブドメイン化で**デモを作り直さない**。これ以上は作らない（YAGNI）。

### S-1. 差し替えは“ローダ境界”に集約（コンポーネントは直接読まない）
| 境界 | デモ実装 | 本番実装 | 署名（不変） |
|---|---|---|---|
| `getBuddy()` | local / demo-seed | LIFF | `Promise<BuddyRecord\|null>` |
| `loadCharacters()` | 静的 `CHARACTERS` | Supabase `display_characters` | `Promise<SelectableCharacter[]>` |
| `loadSponsors()` | `config.sponsors[]` | `display_characters(sponsor)`＋`tap_コンテンツ` | `Promise<Sponsor[]>` |
| `isUnlocked(id, progress)` | `tier==='starter'`（hiddenは常にlock） | 解放ルール（S-3） | `boolean` |
| `track(type, meta)` | no-op/console（enum+meta） | `tap_events` insert | 不変（§6.3） |
> コンポーネントはこの**5境界にだけ依存**。本番は中身を差し替えるだけ＝**改修ゼロ**。

### S-2. データの形を本番想定で今ロック（埋めるのは本番）
- `SuwapuyoProgress` に `login_days/streak/unlocked_character_ids/selected_buddy` を**今から持つ**（§4.4）。デモはstarterのみ・解放は書かない。本番ルールがここに追記＝**後からマイグレ不要**。
- **ID整合**: `characters.ts` の `id` は **`display_characters.id` と一致**（`sample-*`）。CMS統一時に1:1対応＝ID付け替え不要。
- `BuddyRecord.artworkId` 保持＝本番で artwork/LIFF/CMS と突合可能。

### S-3. 解放ルールは“定義だけ”今ロック（実装は本番）
- ルール仕様（`03`§3）: **体操の累計回数／継続日数(streak)／部位コンプ**で hidden を解放。
- デモ: `unlockRule(progress): string[]` は **starterを返すstub**（hiddenは開かない）。だが**素データ（counts/login_days/streak）は今から記録**＝本番はルール本体を書くだけ。
- 「隠し→解放」**演出フックは呼び場所だけ**用意（デモは発火しない）。

### S-4. コンポーネントのpropは本番レイヤを想定
- `TaisouInterlude` に `sponsor?: Sponsor`（デモ未使用・本番で監修紹介を渡す）＝署名を後で変えない。
- `CharacterSelectScreen` は `isUnlocked()` 経由（デモhidden固定・本番で解放反映）。

### S-5. 配信オリジンの継ぎ目
- すわぷよは `getBuddy()` のみ依存（same-origin前提を**ロジックに埋めない**）。本番サブドメイン化は**書き込み側(LIFF/code)だけ**差替＝読取側無改修。

### S-6. 計測点は今から正しい位置に（enum+meta）
- 後付けは漏れる（`07`§11）。デモはno-opでも**呼び場所と引数(enum+meta)を確定**（§6.3）。
```
