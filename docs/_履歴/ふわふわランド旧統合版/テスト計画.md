## 2. 結合テスト観点

### 2.1 登録 → 表示

観点:

- 画像選択後にプレビューが出る。
- 登録後に作品IDが発行される。
- 表示画面に5秒以内に追加される。
- 登場アニメーションが分かる。

合格:

- 10件連続登録で失敗0〜1件。
- 失敗時も再登録で復旧できる。

### 2.2 画像処理 → 表示品質

観点:

- 白背景が透明化される。
- 作品の線が消えない。
- 薄い色が消えすぎない。
- 影が許容範囲か。
- 透明化失敗時に四角表示へ逃がせる。

合格:

- サンプル10枚中8枚以上が実用品質。
- 残り2枚も再撮影または四角表示で運用可能。

### 2.3 スタッフ操作 → 表示状態

観点:

- 全リセットで表示が空になる。
- ランダム表示で作品が再配置される。
- 指定表示で対象作品が大きく出る。
- 非表示にした作品が再登場しない。

合格:

- 操作後の状態がスタッフ画面と表示画面で一致する。

### 2.4 保存 → 復旧

観点:

- 登録作品がブラウザ再読み込み後も残る。
- 表示中状態が復元される。
- 復元できない場合も作品一覧から再表示できる。

合格:

- 表示PCのブラウザ再読み込みから30秒以内に運用再開。

## 3. システムテスト観点

### 3.1 6時間運営シミュレーション

目的:

実際に6時間待つ前に、短時間で状態変化を高頻度に発生させ、メモリ/描画/状態破綻を確認する。

手順:

1. サンプル作品を50件登録。
2. 同時表示数を12に設定。
3. 10秒ごとにランダム入替。
4. 10分以上連続稼働。
5. 途中で指定表示・非表示・リセットを実行。
6. ブラウザを再読み込み。

合格:

- 画面停止なし。
- 操作不能なし。
- 作品プール消失なし。
- メモリが増え続けない。

### 3.2 表示数テスト

| ケース | 同時表示数 | 目的 |
|---|---:|---|
| ST-001 | 8 | 視認性最高の基準 |
| ST-002 | 12 | 標準運用 |
| ST-003 | 20 | 混雑時運用 |
| ST-004 | 30 | 上限候補 |

合格:

- 12体で十分に見やすい。
- 20体でも作品が判別できる。
- 30体は性能確認用であり、UXが悪ければ採用しない。

### 3.3 モニター環境テスト

想定:

- 一般的なDELL 24インチ前後。
- 1台表示。
- 2台連結相当の横長表示。

観点:

- 子どもの目線から見えるか。
- 作品が小さすぎないか。
- 端に寄った作品が見切れないか。
- 主役表示が分かりやすいか。

### 3.4 スタッフ1人運用テスト

手順:

1. 作品10枚を用意する。
2. スタッフ1人で撮影/登録/表示を実施。
3. 1枚ごとの処理時間を測る。
4. 途中で1枚を非表示、1枚を再撮影する。
5. 子どもが待っている想定で指定表示を行う。

合格:

- 平均60秒以内。
- 操作説明を見なくても2周目以降は迷わない。
- 失敗時に詰まらない。

### 3.5 個人情報・同意テスト

観点:

- 撮影台に作品だけ置けるか。
- 顔や名札が写り込まないか。
- 名前入力なしで運用できるか。
- SNS利用同意をイベント表示同意と分離できるか。

合格:

- MVPは `event_only` 前提で運用できる。
- SNS転用は別導線にできる。

## 4. 結合テストケース

| ID | 操作 | 期待結果 |
|---|---|---|
| IT-001 | 画像を1件登録 | 作品IDが発行され、一覧に出る |
| IT-002 | 登録して表示 | 表示画面に作品が登場する |
| IT-003 | 5件登録してランダム表示 | 指定数だけ表示される |
| IT-004 | 作品を主役表示 | 対象作品が大きく中央寄りに出る |
| IT-005 | 非表示 | 対象作品が消え、ランダム候補から外れる |
| IT-006 | 全リセット | 表示中作品が消え、作品プールは残る |
| IT-007 | リロード | 登録作品が復元される |
| IT-008 | 画像処理失敗 | 四角表示または再撮影に逃げられる |

## 5. システムテストケース

| ID | 操作 | 合格基準 |
|---|---|---|
| STC-001 | 50件登録済みで10分連続ランダム入替 | 停止なし |
| STC-002 | 同時表示12体で操作を繰り返す | カクつきが気にならない |
| STC-003 | 同時表示20体で操作を繰り返す | 作品判別可能 |
| STC-004 | 同時表示30体で負荷確認 | クラッシュなし。ただしUXは別判断 |
| STC-005 | 表示中に全リセット10回 | 状態破綻なし |
| STC-006 | 表示中にリロード5回 | 30秒以内に復旧 |
| STC-007 | 10作品を1人で連続登録 | 平均60秒以内 |

## 6. 2026-06-25 判定

### Go

以下を満たす場合、8/2向けMVP開発を進める。

- 画像登録から表示までの流れが成立。
- 12体表示で見やすく安定。
- 20体表示でも破綻しない。
- リセット/指定表示/非表示が動く。
- リロード復旧できる。
- 1人運用の見通しがある。

### Conditional Go

以下の場合は、スコープを落として進める。

- 背景除去が不安定だが、四角表示なら成立する。
- スタッフ端末連携は難しいが、表示PC単体なら成立する。
- ランダム表示は成立するが、指定表示UIが粗い。

### No-Go

以下の場合は、8/2ではデジタルワールド常設を見送り、事前登録サンプル表示や動画展示へ切り替える。

- 作品登録が平均2分以上かかる。
- 12体表示でもクラッシュ/停止が出る。
- リロード復旧できない。
- 撮影時に個人情報写り込みを避けられない。
