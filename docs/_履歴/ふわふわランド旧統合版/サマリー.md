# ふわふわランド サマリー v0.1

> 最終更新: 2026-06-23

## 1. 実装ルール

### 1.1 スコープ

2026-06-25 までは、可否判断に必要な技術検証だけを実装する。

優先:

- 作品登録。
- 画像プレビュー。
- 白背景除去の最小検証。
- PixiJS表示。
- ふわふわ移動。
- リセット。
- ランダム表示。
- 指定表示。
- 非表示。
- ローカル復旧。

後回し:

- AIコメント生成。
- AIキャラ化。
- SNS自動投稿。
- 本番DB。
- ログイン。
- 複雑な管理権限。

### 1.2 ファイル責務

1ファイル1責務を守る。

推奨構成:

```txt
src/fuwafuwa-land/
  types.ts
  data/
    sampleArtworks.ts
  store/
    artworkStore.ts
  image/
    processArtworkImage.ts
  renderer/
    FuwafuwaWorld.ts
    artworkMotion.ts
  components/
    StaffPanel.tsx
    DisplayScreen.tsx
    ArtworkPreview.tsx
    ArtworkList.tsx
```

### 1.3 TypeScript

- `any` 禁止。
- 外部入力は `unknown` から型ガードする。
- 作品IDやステータスはunion型で定義する。

### 1.4 セキュリティ

- `.env*` を触らない。
- シークレットをコミットしない。
- 子どもの名前・顔写真を必須にしない。
- SNS利用同意はイベント表示同意と分ける。

### 1.5 UX

- 100〜200体同時表示は採用しない。
- 標準同時表示は12体。
- 子どもが自分の作品を見つけられることを優先する。
- 失敗時にスタッフが迷わないボタン設計にする。

## 4. ディレクトリ判断

今回の判断:

- `suwapuyo` 内で進める。
- ふわふわランドとショート動画は同一リポジトリでよい。
- ただし実装ディレクトリは分ける。

理由:

- キャラ素材・世界観・YourTIME文脈は共通。
- 企画横断のアイディアを拾いやすい。
- 既存SuwaPuyoのPixiJS/キャラ資産を活用できる。
- 一方で、ふわふわランドとショート動画は実行形態が違うため、同じアプリに混ぜると保守性が落ちる。
