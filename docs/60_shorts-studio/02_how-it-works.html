Shorts Studio · how it works

これ、どうやって
作ってるのか

結論：特定のOSS製品ではありません。無料の部品4つを、約200行の小さな自作スクリプトで貼り合わせているだけ。だから軽くて、ブラウザも要らず、量産にそのまま化けます。

01 — 一言で

1コマずつ画像として描いて、それをffmpegで動画に綴じる。
音は数式で合成。それだけ。

Remotion でも Revideo でも CapCut でもありません。「動画編集ソフト」を一切使わず、プログラムが紙芝居を1枚ずつ描いて、最後にパラパラ漫画として綴じています。

02 — 使っている部品（全部無料・大半は最初から入っていた）
部品役割正体
Python全体の指揮標準。スクリプト言語
Pillow (PIL)1コマを画像として描く（背景・キャラ・字幕を重ねる）OSS画像ライブラリ
NumPy画像のピクセル計算＋音の波形を合成OSS数値計算
ffmpegコマ→mp4 に符号化＋音と映像の結合OSS動画処理の定番
Noto CJK フォント日本語字幕の描画Google製・無料フォント（OSに同梱）
$0追加インストール不要だった ブラウザ不要ヘッドレス（画面なしで動く）商用OK
03 — 核心の仕掛け

「動画」を作っていない。
画像を大量に作っている。

動画は本質的に「1秒30枚の静止画」。だから難しく考えず——毎コマ、背景の上にキャラと字幕を置いた画像を1枚作り、ffmpegに流し込む。30fps×17秒なら522枚。これをパラパラ漫画として綴じれば動画になります。

script.json→Pythonが522コマを描画→ffmpegへ流す→mp4+合成した音→完成

“可愛い・生きてる”は、毎コマでキャラの位置をほんの少しずらすこと（ふわふわ＝サイン波、喋る子＝ぴょこ跳ね）と、字幕のポップインから出ています。生成AIでキャラを描き直しているのではなく、あなたの絵をそのまま動かしている＝ブランドが崩れない。

04 — 5つのレイヤー

1コマは、この5層の重ね合わせです（下ほど手前）。

1

背景

村のイラストを画面いっぱいに。背景はキャラ一貫性が要らないのでAI生成もOK。

2

キャラ

立ち絵を左右に。常時ふわふわ（サイン波）＋喋る子はぴょこ跳ね。

3

上部タイトル＋常設イラスト

「お口で遊ぼう」の帯と、はぐりんを毎コマ描画。

4

字幕

角丸の帯＋日本語。もぐぴよ＝青枠／わーわー＝オレンジ枠と話者で色分け。ポップイン。

5

音（あとで結合）

animalese（すーすーわーわー語）＋ほんわかBGMを数式で自前合成。著作権フリー。

05 — 量産の背骨

script.json を差し替えるだけ

絵の描き方（render.py）は固定。台本・キャラ・色・タイトルは全部 script.json という"データ"に分離してあります。だから新作は、このデータを書き換えて1コマンド走らせるだけ。出展者紹介ショートも同じ型に流し込めます。

# script.json（抜粋）— ここを変えれば別動画
"characters": {
  "mogu": { "img": "...もぐぴよ.png", "side": "left",  "color": [56,152,224] },  // 青
  "wawa": { "img": "...わーわー.png", "side": "right", "color": [222,120,44] }   // オレンジ
},
"lines": [
  { "who": "mogu", "text": "わーわー、お口であそぼ！", "dur": 2.4 },
  { "who": "wawa", "text": "あそぶ！どうやって？",     "dur": 2.2 }
]
台本を書く→python3 shorts/render.py→mp4が出る
06 — 音も“買って”いない

animalese と BGM は自前合成

声＝animalese：字幕の文字数だけ短い電子音（ブリップ）を、キャラごとのピッチで鳴らす＝どうぶつの森風の可愛い喋り。中身の啓蒙メッセージは字幕が担うので、健康効果を“声で言わない”＝医療広告の事故も避けやすい。

BGM＝ほんわかパッド：I–V–vi–IV のやさしい和音を NumPy のサイン波で生成。市販曲を使わないので著作権の心配ゼロ。声の下で小さく流れます。どちらも後で本物の素材に差し替え可能。

なぜ自前合成か

子ども×健康×商用ブランドでは、市販曲・TikTok音源は一発アウト。自分で作った音なら権利が100%クリーン。しかもキャラ別ピッチは“すーすーわーわーの声”というブランド資産になります。

07 — なぜこの作り方にしたか
候補判定理由
Remotion不採用企業利用が有料・頭数管理（既存方針 D-7）
Revideo / Motion Canvas保留良いがブラウザ(chromium)が必要で重い・環境依存
CapCut / 動画編集ソフト不採用手作業で毎回ゼロから＝量産できない・OSSでない
Python+PIL+ffmpeg（採用）採用ヘッドレスで確実・$0・ブラウザ不要・データ駆動で量産・全部自前で権利クリーン
08 — ファイルの地図
ファイル役割

shorts/script.json台本データ。新作はここだけ変える
public/assets/characters/小夏さんの実キャラ23体（透過PNG）
public/assets/ui/village_bg.png背景
shorts/out/*.mp4書き出した動画
docs/60_shorts-studio/01_first-video-recipe.md作り方の手順書（正）

要するに——「動画編集」ではなく「プログラムで紙芝居を量産する」仕組み。台本を変えるたびに、世界観を保ったショートが1本、確実に生まれます。
