# UI/UX Design

## UX方針

中心体験は「作る」ではなく「今日の候補を判断し、少し直して、承認する」。

非エンジニアが毎日使うため、自由度より迷わなさを優先する。

MVPではSNS投稿API連携を扱わない。UX上のゴールは「MP4出力まで迷わず完了し、人間が投稿できる状態になること」。

## 最初から最後までの画面フロー

```text
今日
  -> 投稿枠を選ぶ
  -> 自動生成
  -> 候補を選ぶ
  -> レビュー
  -> 高速プレビュー
  -> MP4生成
  -> MP4ダウンロード
  -> 投稿文/ハッシュタグ確認
  -> 手動投稿
  -> 学習へ反映
```

## 実装対象ワークフロー

MVPはSNS投稿APIを含めない。完了地点は `MP4出力 + 手動投稿に必要な情報の表示 + 学習反映`。

2026-06-26時点の実装済み導線は、Web UI内で直接MP4生成までは行わない。MP4出力画面ではrender.py互換JSONダウンロード、CLI command copy、caption copy、hashtags copyを提供し、実際の `--check` とMP4生成はCLIで行う。

実装者は次の順で画面状態を進める。

```text
1. Dashboard
2. Slot Setup
3. Candidate Generation
4. Candidate Selection
5. Review Editor
6. Preview Check
7. MP4 Render
8. Manual Post Kit
9. Learning Review
10. Done
```

各ステップは1つの主ボタンだけを強く表示する。副ボタンは薄く表示し、迷わせない。

### 状態

動画カードには必ず状態を持たせる。

- 未生成
- 生成済み
- レビュー待ち
- 修正中
- 高速プレビュー済み
- MP4生成待ち
- MP4生成中
- MP4出力済み
- 手動投稿済み
- 学習反映済み

### 状態とUI制御

| 状態 | 画面表示名 | 主ボタン | 無効条件 | 成功時の次状態 | 失敗時の表示 |
| --- | --- | --- | --- | --- | --- |
| `slot_empty` | 未生成 | `候補を作る` | ターゲット/テーマ/目的が未設定 | `generating_plan` | 入力不足を該当フィールド下に表示 |
| `generating_plan` | 候補生成中 | なし | 常に無効 | `candidate_ready` | `候補生成に失敗しました` |
| `candidate_ready` | 候補あり | `この案でレビュー` | 候補未選択 | `reviewing` | なし |
| `reviewing` | 修正中 | `高速プレビュー` | タイトル/セリフ/キャラが空 | `preview_ready` | バリデーションエラー表示 |
| `preview_ready` | プレビュー済み | `MP4生成へ` | 必須チェックにエラーあり | `render_queued` | エラー項目へスクロール |
| `render_queued` | 生成待ち | `MP4を生成` | 内部JSON未生成 | `rendering` | `生成データを作れませんでした` |
| `rendering` | MP4生成中 | なし | 常に無効 | `mp4_ready` | `render_failed` |
| `render_failed` | 生成失敗 | `再生成` | なし | `rendering` | 同じ画面に原因を表示 |
| `mp4_ready` | MP4完成 | `MP4をダウンロード` | ファイル未生成 | `manual_post_ready` | ダウンロードエラー表示 |
| `manual_post_ready` | 投稿準備OK | `手動投稿済みにする` | MP4ダウンロード未チェック | `posted_manually` | チェック不足表示 |
| `posted_manually` | 手動投稿済み | `学習へ送る` | なし | `learning_review` | なし |
| `learning_review` | 学習確認 | `次回ルールに反映` | 理由未選択 | `learned` | 理由選択を促す |
| `learned` | 完了 | `今日へ戻る` | なし | ダッシュボード | なし |

### 共通レイアウト

全画面で共通して次の構造にする。

- 左: 投稿枠/候補/キャラなどの一覧
- 中央: 現在選択中の動画プレビューまたは状態説明
- 右: いま操作すべき設定パネル
- 下: ステップバー、品質チェック、補足情報

画面幅が狭い場合は次の順に縦積みにする。

1. ステップバー
2. プレビュー
3. 主操作パネル
4. 一覧
5. 品質チェック

常に表示する上部情報。

- 画面名
- 今日の日付
- 今日の完了数
- 次のおすすめ行動
- 現在の動画ステータス

上部文言:

```text
今日のショート運用
あと {remainingCount} 本、MP4出力まで進めます。
```

次アクション文言:

```text
次は「{nextActionLabel}」です。
```

### ステップバー

ステップバーは全工程を表示する。

```text
投稿枠 -> 候補 -> レビュー -> プレビュー -> MP4生成 -> 投稿準備 -> 学習
```

ステップ表示ルール。

- 完了: チェックアイコン
- 現在: 強調色
- 未来: 薄い色
- エラー: 赤系バッジ
- 警告: 黄系バッジ

ステップを押した時の挙動。

- 完了済みステップ: 戻れる
- 現在ステップ: 何もしない
- 未来ステップ: 条件未達なら進めない理由を表示

未来ステップを押した時の文言:

```text
まだ進めません。先に「{requiredStep}」を完了してください。
```

## 画面

### 今日の運用ダッシュボード

最初に表示する画面。候補編集より先に、今日の運用状態を見せる。

表示するカード。

- 今日の投稿目標: `3本`
- MP4出力済み: `{doneCount}本`
- レビュー待ち: `{reviewCount}本`
- 未生成: `{emptyCount}本`
- 次のおすすめ行動

投稿タイムライン。

| 枠 | 表示例 | クリック時 |
| --- | --- | --- |
| 朝 | `08:00 口たいそう / レビュー待ち` | レビュー画面へ |
| 昼 | `12:30 雨の日の選び方 / 未生成` | 投稿枠設定へ |
| 夜 | `19:00 親子でふわふわ / MP4出力済み` | MP4出力画面へ |

主ボタン。

- 未生成枠がある: `次の候補を作る`
- レビュー待ちがある: `レビューを再開`
- MP4生成待ちがある: `MP4を生成`
- すべて完了: `今日の学習を見る`

空状態文言:

```text
今日の投稿枠がまだありません。まず朝・昼・夜の枠を作ります。
```

エラー状態文言:

```text
今日のデータを読み込めませんでした。再読み込みしてください。
```

### 投稿枠設定画面

目的は、候補生成に必要な最小条件を決めること。

入力項目。

- 投稿枠名
- 想定投稿時間
- 主ターゲット
- テーマ
- 投稿目的
- 1人/2人
- キャラ指定

主ターゲット選択肢。

- なんとなく体に不調を感じている人
- 健康について正しく知りたい人
- 親子で楽しく健康になりたい人
- 医療従事者・専門職・出展者

テーマ選択肢の初期値。

- 口腔育成
- 鼻呼吸
- 未病
- からだの不調
- 親子の健康習慣
- YourTIMEイベント
- 雑談から健康につなげる

投稿目的選択肢。

- 一緒に口を動かす
- 親子の会話を作る
- YourTIMEへ興味を持ってもらう
- 健康知識をやさしく届ける
- 専門家にも違和感なく見せる

主ボタン。

- `候補を作る`

進行条件。

- 主ターゲットが1つ選択されている
- テーマが1つ選択されている
- 投稿目的が1つ選択されている

入力不足文言:

```text
候補を作るには、主ターゲット・テーマ・投稿目的を選んでください。
```

### 候補生成中画面

生成中は、ただのローディングにしない。何を作っているかを表示する。

表示する進行ラベル。

- キャラ相性を見ています

- タイトル雰囲気を選んでいます
- 30-60秒に収まるように整えています
- YourTIMEらしさを確認しています

```text
今日の候補を作っています。タイトル、セリフ、演出、投稿文までまとめて用意します。
```

- `もう一度作る`
- `投稿枠を見直す`

失敗文言:

```text
候補生成に失敗しました。投稿枠の設定を見直すか、もう一度作ってください。
```

#### タイトル雰囲気

タイトル雰囲気は選択式にする。自由CSS編集は出さない。

| ID | 表示名 | 見た目 | 推奨用途 |
| --- | --- | --- | --- |
| `puku-yellow` | ぷくっと黄色 | 黄色ベース、太め、丸い | 親子実践、朝の導入、わーわー主役 |
| `teacher-green` | 先生みどり | 緑アクセント、少し落ち着く | 健康知識、医療従事者向け、整理回 |
| `fuwa-blue` | ふわ水色 | 水色ベース、余白やわらかめ | つながり、雑談、やさしい回 |
| `kiratto-peach` | きらっと桃 | 桃色、明るい、少しきらっと | 美容、未病、笑顔、ラピ子回 |
| `hand-white` | 手書き白 | 白地、手書き感、説明感少なめ | 村の会話、日常雑談、ゆるい導入 |
| `adventure-orange` | 探検オレンジ | オレンジ、少し傾き、発見感 | 小ぼけ、冒険、チャレンジ、わーわー回 |
| `night-drop` | 夜のしずく | 濃色、落ち着き、余韻 | 睡眠、鼻呼吸、夜の習慣 |
| `fire-red` | 火消し赤 | 赤系アクセント、注意をかわいく | 炎症、糖化、酸化などの注意喚起 |

タイトル雰囲気のランダム選択ルール。

- 親子向け: `puku-yellow` / `fuwa-blue` を優先
- 医療従事者向け: `teacher-green` / `hand-white` を優先
- YourTIME告知: `adventure-orange` / `puku-yellow` を優先
- 雑談: `hand-white` / `fuwa-blue` を優先
- 未病美容: `kiratto-peach` / `teacher-green` を優先
- 炎症/糖化/酸化: `fire-red` / `teacher-green` を優先
- 同じ雰囲気を3本連続で使わない

### MP4出力画面

投稿API連携前の最重要画面。

現MVPでは、この画面を「ローカル直接MP4生成画面」として扱う。開発サーバでは、ボタン押下でVite middlewareがPython/ffmpegを起動する。本番/previewで実行ブリッジがない場合は、JSON/CLIの半自動出力画面として使う。

表示:

- レンダリング状態
- 出力ファイル名
- 尺
- サイズ
- 最終確認チェック
- MP4ダウンロード
- 投稿文下書き
- ハッシュタグ
- 手動投稿チェックリスト

操作:

- MP4生成（Web UI直接生成版。現MVPでは未実装）
- 再生成
- JSONダウンロード
- CLIコマンドコピー
- 投稿済みにする
- 学習へ送る

#### MP4生成画面の詳細

MP4生成は、ユーザーが待てるように現在状態を明確にする。

生成中に表示するもの。

- 現在の処理名
- 経過時間
- 出力予定ファイル名
- 生成対象の尺
- `レビューへ戻る`

生成中の処理名例。

- レイアウトを固定しています
- フレームを書き出しています
- 音声を合わせています
- MP4にまとめています
- 最終確認をしています

生成成功時に表示するもの。

- MP4プレビュー
- ファイル名
- 尺
- 解像度
- ファイルサイズ
- `MP4をダウンロード`
- `投稿準備へ`

生成失敗時に表示するもの。

- ユーザー向け原因
- 再生成ボタン
- レビューへ戻るボタン
- 詳細エラーを開く

ユーザー向け原因の分類。

- 素材が見つからない
- 字幕が長すぎる
- レンダリングに失敗した
- 出力先に保存できない
- 不明なエラー

失敗文言:

```text
MP4生成に失敗しました。素材や字幕を確認して、もう一度生成してください。
```

成功文言:

```text
MP4が完成しました。ダウンロードしてSNSへ手動投稿できます。
```

#### 半自動MVPの表示

実装済みの半自動MVPでは、次を表示する。

- `JSONをダウンロード`
- `CLIコマンドをコピー`
- `python3 shorts/render.py --check {jsonPath}` の案内
- 期待されるMP4出力先
- caption copy
- hashtags copy

`--check` の結果で止めるべきエラー。

- `schema_invalid`
- `asset_missing`
- `layout_out_of_bounds`
- `duration_out_of_range`

`unsupported_animation` は警告扱い。MP4生成自体は進められるが、該当演出はrendererで無視される可能性がある。

### フィードバック画面

承認/却下/修正を自然に学習へ返す。

却下理由:

- 面白くない
- キャラらしくない
- テンポが悪い
- テロップが読みにくい
- 内容が危ない
- ブランドに合わない

承認理由:

- テンポがいい
- キャラが合っている
- オチがいい
- 投稿向き
- 再利用したい

修正時:

- セリフ変更
- レイアウト変更
- キャラ変更
- 尺変更

各修正は `次回から反映` / `今回だけ` を選べる。

### 学習画面

学習画面は単なるメモではなく、次回生成のルール候補を確認する画面にする。

表示。

- 今回採用した候補
- 修正前/修正後の差分
- 採用理由
- 却下理由
- 次回ルール候補
- `今回だけ` / `次回から反映`

次回ルール候補の例。

- タイトルYは今回より下げる
- 冒頭の天気は分かりやすくする
- わーわーは説明口調を避ける
- もぐぴよは子どもが真似できる口の動きを入れる
- 2人会話ではキャラを向き合わせる

主ボタン。

- `次回ルールに反映`

進行条件。

- 採用/却下/修正理由のいずれかが1つ以上ある

理由がない場合の文言:

```text
次回に活かす理由を1つ選んでください。
```

保存成功文言:

```text
次回ルールに反映しました。同じズレを減らします。
```

## プレビュー

3段階にする。

### 高速プレビュー

- PNG 1枚
- 数秒で確認
- layoutと字幕確認

### 本番プレビュー

- mp4
- 承認前に確認

### 差分プレビュー

- 修正前後を並べる
- セリフ・位置・キャラ変更が見える
