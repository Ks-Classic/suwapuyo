# 07 すわぷよ LINE公式アカウント・単一LIFF仕様

> 初回決定: 2026-07-10
> 統合決定: 2026-07-13
> 対象: YourTIME.来場前・当日・開催後の「すわぷよ」体験
> 状態: 体験入口と認証境界の正本。本番ID、作品claim、DB、出展者レポートは各Gate通過後に実装する。

## 0. 決定

LINE公式アカウントを体験全体のホームとし、通常利用者は友だち追加後、トーク画面のリッチメニューからすわぷよ、会場マップ、ブース案内、日時・アクセスへ入る。

Web体験は**すわぷよ専用LIFF 1つ**へ統合する。旧「会場案内所LIFF」は別アプリとして維持せず、必要な機能を同一LIFFのrouteへ移す。`VITE_LIFF_ID`は移行完了後に廃止し、公開LIFF IDは`VITE_SUWAPUYO_LIFF_ID`だけを正とする。

```text
LINE公式アカウント
  ├─ あいさつメッセージ
  └─ リッチメニュー（通常入口・再訪入口）
       ├─ /                 すわぷよ
       ├─ /village/map      会場マップ
       ├─ /booths           ブース案内
       ├─ /stamps           スタンプ帳
       └─ /event/...        チェックイン等

作品固有QR（例外入口）
  └─ /claim/{opaque_token}  自分の作品を受け取る
       └─ 受取後はLINE公式アカウントのリッチメニューへ合流
```

## 1. 公式アカウントとLIFFの役割

### 1.1 LINE公式アカウント

- 友だち追加、最初の歓迎、リッチメニュー、イベント前後の通知、再訪を担当する。
- 利用者にとっての固定ホームはLINE公式アカウントであり、LIFF IDやログインを入口名として見せない。
- 開催前、当日、開催後のリッチメニュー切替は運営設定を正とし、端末時刻だけで切り替えない。

### 1.2 単一LIFF

- ゲーム、キャラ受取、体操、ブース、マップ、チェックイン、スタンプをrouteで分ける。
- 初回は`liff.init()`、必要時のLINEログイン、友だち状態確認を行う。
- 個人状態を扱うrouteは、サーバーが検証したLINE ID tokenから内部利用者を確定する。
- LINEの表示名やプロフィール画像を永続保存せず、生のLINE user IDをURL、画面、ログ、analyticsへ出さない。

### 1.3 ログイン・友だち追加・サービス同意を分離する

| 境界 | 目的 | 代替しないもの |
|---|---|---|
| LINEログイン | 同じ利用者の安全な識別 | 友だち追加、子ども情報の利用同意 |
| 友だち追加 | リッチメニュー、通知、再訪 | サービス側の個人データ利用同意 |
| サービス同意 | 保存項目、利用目的、変更・削除の確認 | LINEの認可・友だち追加 |

友だち追加を「データ取得のため」とだけ説明しない。`描いたキャラとまた遊べる`、`お口体操を続けられる`、`イベント情報へ戻れる`という利用者価値を先に示す。

## 2. 通常入口

```text
公式アカウントQR／紹介リンク
  ↓
友だち追加
  ↓
あいさつメッセージ
  ↓
リッチメニュー
  ↓
すわぷよ／マップ／ブース／日時・アクセス
```

- 公式アカウントQRを、事前告知とツナやすブースの一般入口にする。
- すわぷよ起動時は友だち状態を確認し、未追加またはブロック中なら理由を短く説明して追加・解除を促す。
- LINE内ではログイン操作を意識させず、外部ブラウザでは必要時だけLINEログインへ遷移する。
- リッチメニューから開いたrouteは同じLIFFセッションを利用し、画面ごとにログインを繰り返さない。

## 3. 作品QR入口

作品QRは公式アカウントに代わる別ホームではなく、自分の作品を受け取るための例外的なdeep linkとする。

```text
作品登録成功
  ↓
作品固有QR
  ↓
/claim/{opaque_token}
  ↓
LINEログイン・サーバー検証
  ↓
受取対象の確認
  ↓
利用目的確認・友だち追加
  ↓
claimを確定
  ↓
キャラ選択／すぐ遊ぶ
  ↓
「次からはLINEのメニューから会えるよ」
```

### 3.1 token要件

- QRに作品ID、LINE user ID、連番利用者IDを直接含めない。
- tokenは推測不能なopaque値とし、サーバーで作品へ解決する。
- 一回限り、有効期限、失効、使用済み、campaignを検証する。
- 同じ作品の二重claim、QR転送、誤読取、紛失、再発行を扱う。
- claim確定は冪等にし、通信再送で二重付与しない。
- 本番schema、署名、RLS、失効運用はCHECKIN-106/107相当のGate通過前に実装しない。

### 3.2 復旧

- 作品QRを失くした人、作品を作らない人、登録失敗者は公式アカウントQRから通常体験へ入れる。
- 親のLINEアカウントで複数の子ども・複数作品を扱える形を保つ。
- ブロックや一時通信障害で作品データを削除せず、再追加・再試行後に復帰できるようにする。

## 4. 機能別Gate

| 機能 | LINEログイン | 友だち状態 | 備考 |
|---|---:|---:|---|
| すわぷよ | 必須 | 必須 | 現行の公開条件 |
| 作品受取・キャラ保存 | 必須 | 必須 | サーバー検証後にclaim |
| 継続記録・お口体操 | 必須 | 必須 | 同じ内部利用者へ保存 |
| チェックイン・スタンプ | 必須 | 本番判断 | campaignとQR検証が必要 |
| 会場マップ・基本案内 | 通常は公式アカウントから開く | 通常入口では追加済み | 紙・通常URL等の障害時fallbackを別途用意 |

全routeを同一の画面Gateで遮断するのではなく、個人状態を扱うrouteだけ厳密に認証する。ただし通常導線は公式アカウントへ統一する。

## 5. あいさつメッセージ

```text
ようこそ、すーすーわーわーの村へ！

親子で遊べる「すわぷよ」や、
YourTIME.の会場案内をこのLINEから見られます。

下のメニューから、すぐ遊べます。
```

- 主役はリッチメニューとし、あいさつへ多数のリンクを詰め込まない。
- 友だち追加直後に取得データを保存しない。個人データはLIFF内のサービス同意後だけ保存する。
- 配信頻度、運営主体、問い合わせ・停止方法は公開前に確定する。

## 6. データとレポート境界

### 6.1 最小データ

```text
game_users
  id, verified_line_subject, first_source,
  first_played_at, last_played_at,
  consent_version, consented_at

game_events
  id, user_id, campaign_id, event_name, occurred_at, properties

artwork_claims（将来）
  token_hash, artwork_id, claimed_by_user_id,
  expires_at, claimed_at, revoked_at
```

- クライアントが送るLINE user IDやプロフィールを本人確認の正にしない。
- ID tokenをサーバーで検証し、内部利用者IDへ変換する。
- 同意前は子どもの年月・性別、作品claim、個人単位analyticsを保存しない。
- URL、QR、ログ、analytics propertyに個人情報を入れない。

### 6.2 還元

- 出展者へ個人別来場者一覧を渡さない。
- 訪問、自己申告の説明・体験・購入、ゲーム開始、継続は定義を分ける。
- 子どもの年月・性別と個別感想を組み合わせない。
- YourTIME.・ツナやす・出展者のデータ取得主体、利用目的、保持、削除、第三者提供はBRAND-105で確定する。
- 少数値抑制とレポートの最小集計人数を決定するまで、本番レポートへ個人データを接続しない。

## 7. 設定と秘密情報

| 値 | 配置 | 公開性 |
|---|---|---|
| `VITE_SUWAPUYO_LIFF_ID` | ローカル`.env.local`とCloudflare向けVite build環境 | 公開可 |
| `VITE_LIFF_ID` | 旧会場案内所の移行完了後に削除 | deprecated |
| `LINE_CHANNEL_ACCESS_TOKEN` | LINE登録CLIを実行するWSL shellの環境変数 | secret |
| `LINE_CHANNEL_SECRET` | Webhookを実装する場合のみCloudflare Worker Secret | secret |

- `VITE_`へトークンやチャネルシークレットを置かない。
- `.env.local`をGitへ入れない。
- 手動Cloudflare Pages deployでは、`VITE_SUWAPUYO_LIFF_ID`を渡してbuildした`dist`を配信する。
- 本番・previewで`VITE_SUWAPUYO_LIFF_MODE=demo`を設定しない。

## 8. 実装段階

1. LINE公式アカウント、Messaging API、単一LIFFの紐付けを確認する。
2. `VITE_SUWAPUYO_LIFF_ID`へ統一し、旧`VITE_LIFF_ID`依存を終了する。
3. 開催前リッチメニューとキーワード応答をテストアカウントへ登録する。
4. リッチメニューからすわぷよ、マップ、ブースを開く実機試験を行う。
5. ID tokenのサーバー検証と内部sessionを実装する。
6. 作品claimのtoken、schema、署名、RLS、復旧をGate通過後に実装する。
7. 集計レポートをデータ責任・少数値基準の決定後に接続する。

## 9. 受け入れ条件

- 通常利用者が公式アカウントのリッチメニューをホームとして迷わず戻れる。
- すわぷよLIFF 1つでゲーム、マップ、ブース、作品claimのrouteを扱える。
- 未追加またはブロック中の利用者は、理由と追加・解除導線を確認できる。
- 追加後、同じLIFF画面で状態を再確認して続行できる。
- 外部ブラウザでもLINEログイン後に元のrouteへ戻れる。
- 作品QRから受け取った後、公式アカウントの通常導線へ合流できる。
- LINE user ID、token、チャネルsecretが画面、URL、ログ、Gitへ出ない。
- 友だち追加とサービス同意が別に説明される。
- iOS／Android LINE実機で、追加、ブロック解除、リッチメニュー、作品QR、復旧を確認する。
