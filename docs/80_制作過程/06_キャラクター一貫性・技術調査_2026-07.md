# いとこキャラ 同一性技術・制作方式 調査と採用判断（2026-07）

> 文書状態: 技術選定SSoT。2026-07-13時点の一次情報を基に、静止画、2D、3D、動画、ライブ配信を横断して比較した
> 最終更新: 2026-07-13
> 対象: いとこキャラ。公式やすキャラは原画不変の別Gateで扱う

## 1. 結論

同一キャラを長期運用する最善策は、単一の生成モデルへ賭けることではない。用途ごとに生成自由度を最小化する。

| 用途 | 第一方式 | 生成AIの役割 | 同一性リスク |
|---|---|---|---:|
| アイコン、プロフィール、定番ポーズ | 作者承認済み2D sourceの合成・変形 | 原則使わない | 最小 |
| 表情会話、短い寸劇、配信 | Inochi2D / Live2D等の2D rig | 背景・案出しまで | 小 |
| ダンス、全身、Zoom、複数角度 | Blender編集正本 + VRM 1.0 + motion retarget | motion補助・背景まで | 小〜中 |
| カルーセルの新規場面 | GPT Image 2等でapproved referenceを編集 | 新しい場面・小物・構図 | 中 |
| 実写motionのキャラ化 | 3D retargetを主力、Wan2.2-Animate等を比較実験 | character animation / replacement | 中〜大 |
| 映画的広告 | keyframe lock付き生成video + compositing | 画作りと補間 | 大 |

生成は速さと表現幅を担当し、キャラの正本は作者承認済みsource、Character Master、Golden Setが担当する。`毎回ゼロから生成する`、`前回生成物だけを次のreferenceにする`、`一つの万能promptで全媒体を作る`は不採用とする。

## 2. 採用アーキテクチャ

```text
Rights Evidence
  ↓
Character Master 1.0.0
  ├─ 2D source / turnaround / parts
  ├─ Blender source / VRM exports
  ├─ Golden Set（回帰評価用・学習用と分離）
  └─ Voice / language / behavior bible
  ↓
Content Brief
  ↓ source selector
  ├─ deterministic 2D
  ├─ rigged 2D
  ├─ deterministic 3D
  ├─ reference-guided image generation
  └─ keyframe/motion-guided video generation
  ↓
Compositing / subtitle / platform audio
  ↓
Character・Rights・Safety・Quality・Factual review
  ↓
Publication asset + manifest + hash + rollback pointer
```

`source selector`は、必要な動き・角度・尺・納期・同一性許容度・媒体・広告利用の有無から制作方式を決める。人が「なんとなく生成」を選ばないようにする。

## 3. 制作方式の選択ルール

### 3.1 決定論的2D

採用対象:

- アイコン、吹き出し、説明カード、固定リアクション、定番CTA。
- 同じ表情・輪郭を何度も使い、制作速度と一致率を最優先する場面。

必要資産:

- 正面、3/4、側面、背面。
- 24表情、32pose、手、足、尾、服、badgeの部品表。
- 線幅、palette、重なり順、輪郭safe area。

画像生成を使うより、承認済み部品の組み合わせが速く安全な場合は必ずこちらを選ぶ。

### 3.2 rigged 2D

`Inochi2D`はBSD-2-Clauseのオープンな2D puppet形式で、Inochi Sessionによるface trackingへ展開できる。一方、開発途上でLive2D互換ではなく、既存Live2D素材は再rigが必要である。OSS再現性を優先するspike候補とし、商用品質・対応者・制作工数はLive2Dと同じ原画で比較する。

比較条件:

- 口形、瞬き、眉、頬、牙、尾、ベスト、手振り。
- 正面、左右30度、上下20度、体傾き、Zoom小窓。
- source納品、commercial runtime、更新、配信PC負荷。

### 3.3 決定論的3D

`Blender`で編集正本を保持し、`VRM 1.0`をstream/render用に書き出す。BlenderのGPLは通常、Blenderで作ったartwork自体へ波及しない。VRMはglTF 2.0を基礎にhumanoid、表情、揺れ、作者・利用条件metadataを扱える。UniVRMはMITである。

注意:

- いとこは人間型でないため、hips、膝、肘、足首、頭身を見た目基準で補正する。
- 尾はVRM humanoid外のcustom bonesとして管理する。
- VRM metadataに書くだけで契約が成立するわけではない。契約・台帳への参照IDを入れる。
- 3Dを2Dと完全一致させるのではなく、媒体差をCharacter Masterで明示する。

### 3.4 参照付き静止画生成

GPT Image 2のproduction workflowでは、参照画像をindex付きで説明し、`preserve`する不変条件と`change only`の変更点を分離し、一度に一つの変更を行う。identity-sensitive editはmedium/high qualityで比較する。

固定するもの:

- reference slotと役割。
- character identity block、negative constraints、用途、camera、背景。
- model、quality、input hash、prompt template version。
- Golden Set regression、3-role review、生成manifest。

生成モデルのseedや同一promptだけを再現性の根拠にしない。provider更新後は必ず回帰評価する。

### 3.5 OSS image conditioning

| 候補 | 現行判断 | 利点 | 制約・Gate |
|---|---|---|---|
| IP-Adapter | spike | Apache-2.0。画像promptとControlNetを併用可能 | scaleを下げるほど多様化するが同一性が落ちる。CLIP center cropに注意 |
| ControlNet | spike | Apache-2.0。pose、depth、edge等で構図を拘束 | identity lockではない。IP-Adapter等と役割分担 |
| DreamBooth | 条件付き将来 | 少数画像からsubjectをpersonalize | 過学習、言語drift、base model/license、学習データ権利を検証 |
| LoRA | 条件付き将来 | 小さく高速な差分weight | weightの配布・漏洩・base model条件を分離。Golden Setを学習に混ぜない |
| StoryDiffusion | R&D | Apache-2.0。長いimage sequenceのcharacter consistency研究 | GPU、base model、production再現性を実測。完成保証ではない |
| CharaConsist | 不採用保留 | FLUX系でforeground/background consistencyを研究 | 2026-07確認時にrepository license不在。許諾確認までproduction禁止 |
| InstantCharacter | production不採用 | single image、tuning-freeの研究 | repository licenseがacademic/research/education限定でcommercial禁止 |
| InstantID / PhotoMaker | 主力不採用 | 人物顔identityで実績 | 人間顔中心。InsightFace等の依存licenseを別確認。爬虫類キャラに不適 |

### 3.6 workflow engine

`ComfyUI`はnode graph、workflow保存、API化に有力で、コードはGPL-3.0である。社内制作環境の候補とするが、次を一括で「ComfyUIだからOSS」と扱わない。

1. ComfyUI本体。
2. custom nodeごとのlicense、commit、source hash。
3. base modelとcheckpointのlicense。
4. LoRA、adapter、VAE、upscaler、face model。
5. 入力画像・motion・音声の許諾。
6. 出力の媒体・広告・再販売条件。

workflow JSON、environment lock、SBOM、asset hashをmanifestへ紐づける。custom nodeにlicenseがなければproductionへ進めない。

### 3.7 動画生成・人物置換

| 候補 | 現行判断 | 用途 | 制約・Gate |
|---|---|---|---|
| Wan2.2-Animate 14B | 有力spike | 演技・表情のanimation、character replacement | repositoryはApache-2.0。正確なcheckpoint、依存、入力権利、GPU、出力をpilotで固定 |
| LTX-Video / LTX-2 | 有力spike | keyframe、LoRA、image-to-video、同期A/V | codeと各checkpointのlicenseを分ける。旧checkpointにOpenRail系あり |
| Google Veo / Flow | closed benchmark | reference ingredients、9:16、複数scene、音声 | provider規約、費用、地域、利用可能model、provenanceを制作時に再確認 |
| Runway Gen-4 References | closed benchmark | 最大3 referenceでvisual consistency | vendor lock-in。reference設計と利用規約をproduction時に確認 |
| Adobe Firefly Custom Models | closed benchmark | Character modelを10〜30画像でtraining | enterprise権限・規約・費用。captionとpermanent attribute設計が必要 |

Wan2.2-Animateは旧記述のように一律`academic/non-commercial`とは扱わない。2026-07時点の公式repositoryはApache-2.0である。ただし、project page、配布checkpoint、依存model、sample input、商標、音源、振付は別レイヤーである。逆に、license不在・研究限定の実装は、結果が優れても広告や有償制作に使用しない。

## 4. datasetを三分割する

### Training Pack

LoRA/custom modelを作る場合だけ使用する。作者承認済み画像、caption、crop、許可範囲、hashを持つ。公開・第三者API送信・weight配布は別許可とする。

### Golden Set

同一性を測る回帰評価専用。学習に混ぜない。neutral、横、背面、全身、顔アップ、尾、手足、衣装、極端な遠近、小サイズ、複数キャラを含む。

### Holdout Stress Set

開発者が調整時に見ない評価専用。未知のpose、occlusion、照明、背景、motionを含め、過学習したpromptやLoRAを検出する。

同じ12枚を学習・prompt調整・最終評価の全てに使うと、実運用の一貫性を過大評価するため禁止する。

## 5. temporal consistency QA

動画は1frameの見た目だけでは合格にしない。

Hard failure:

- 額記号、牙、指、足趾、badge、尾が増減・左右反転・消失する。
- 顔や体色が途中で別個体へ変わる。
- 服が体へ溶ける、関節が外れる、背景人物と融合する。
- 公式やすへ近づきすぎ、単独で誤認される。

測定:

- 1秒ごとのidentity rubric。
- frame間のpalette、landmark、silhouette、mark位置の変化。
- optical flow上の輪郭flicker。
- first / middle / last frameの3-role review。
- 速度を落とした確認、無音確認、32px thumbnail確認。

動画はfirst frameだけでなく、必要に応じてlast frameと中間keyframeを承認済み2D/3Dから固定する。生成後に一部frameだけ描き直して時間的破綻を増やさない。

## 6. 音声・演技の同一性

見た目だけでなく、声、語尾、間、失敗後の反応もidentityである。

- 初期は本人音声、権利確認済みTTS、字幕のみを明示的に選ぶ。
- voice cloneは本人同意、provider規約、用途、削除、再利用、なりすまし対策を別Gateにする。
- いとこは「早い、明るい、反省できる」。悪意、他責、他者いじりで笑いを取らない。
- 自動字幕は事実・商品名・人名・健康表現を人が確認する。

## 7. provenance・license ledger

各公開物に次を保存する。

- コンテンツ ID、Character Master version、source selector結果。
- tool、model、checkpoint、adapter、custom nodeのversionとlicense snapshot。
- input asset ID、許諾証拠 ID、hash。
- prompt / workflow / motion / voice / music / font / logo。
- 人の修正、reviewer、承認日時、公開媒体、広告利用。
- output hash、C2PA/Content Credentialsの有無、rollback先。

C2PA Content Credentialsが付く場合も、SNSや再encodeでmetadataが失われ得るため、内部manifestとhashを正本として残す。

## 8. トレンド・パロディ運用

採用するのは`trend grammar`であり、投稿そのものではない。

抽出してよい候補:

- 冒頭の問題提起、尺、転換回数、視線、画面分割、オチの構造。
- 一般的な動き、編集リズム、字幕の情報順。

そのまま複製しないもの:

- 元動画、特徴的な連続振付、台詞、歌詞、音源、ロゴ、衣装、背景、camera choreographyの組合せ。
- 実在人物の顔・体・声、他者キャラクター、広告表現。

媒体内のremix/music機能を使う場合も、その許諾が他媒体や広告へ持ち出せるとはみなさない。Instagramの一般licensed music libraryはpersonal/non-commercial向けが基本で、商用にはSound Collection等を検討する。TikTok BusinessはCommercial Music Library、YouTube Shortsはproduct内libraryを媒体内で使い、共通masterは無音・無watermarkで保持する。

## 9. 導入順

### Phase A: 今すぐ

1. 権利証拠を台帳化。
2. Character Masterの造形・性格・口調をツナマヨさんと確定。
3. 2D source、turnaround、Golden Set、holdoutを制作。
4. カルーセルを固定2D中心で3本制作し、制作時間と認識率を測る。

### Phase B: 2D / 3D spike

1. Inochi2DとLive2Dを同じ5表情・5動作で比較。
2. Blender/VRM仮モデルで5 motionを比較。
3. 小サイズ、全身、尾、口、Zoom、縦動画を評価。

### Phase C: 生成pilot

1. GPT Image 2で10scene、hard failure 0を目指す。
2. ComfyUI + IP-Adapter + ControlNetを同じbriefで比較。
3. Wan2.2-AnimateとLTX-2を自作motionだけで比較。
4. closed toolを1つだけbenchmarkし、品質・時間・費用・権利説明を比較。

### Phase D: production

pilotを通過した方式だけを`approved production recipe`に昇格する。モデルや規約が変われば自動継続せず、license checkとGolden/Holdout regressionを再実行する。

## 10. 採用Gate

- [ ] キャラの作者・監修・運用責任者と利用範囲が証拠 IDで追える。
- [ ] 2D/3D/AIの差異をCharacter Masterが許可している。
- [ ] code、model、weight、custom node、input、outputのlicenseが別々に確認済み。
- [ ] Training / Golden / Holdoutが分離されている。
- [ ] identity hard failure 0、平均95点、blind recognition目標を満たす。
- [ ] 生成videoはtemporal QAを通過している。
- [ ] 音源・振付・演者・voice・font・logoの許諾がある。
- [ ] manifest、hash、review、rollbackがある。
- [ ] provider/model終了時の代替recipeが1つ以上ある。

## 11. 2026-07調査で判明した現行仕様の不足と修正

| 不足 | 修正 |
|---|---|
| 生成AI中心に読める | deterministic-firstのsource selectorを追加 |
| tool名だけで商用可否を判断し得る | code / model / weight / node / input / outputの6層licenseへ分解 |
| Golden Setを学習にも使い得る | Training / Golden / Holdoutへ三分割 |
| 1frame品質に偏る | temporal QA、keyframe lock、first/middle/last reviewを追加 |
| prompt再現性に依存 | workflow、model、hash、manifest、regressionを必須化 |
| 音声がidentity外 | voice、字幕、演技規則を追加 |
| AI由来表示だけで追跡できる想定 | C2PAと内部manifestを併用 |
| Wan-Animateを一律研究限定 | Wan2.2-AnimateのApache-2.0 repositoryを候補化し、checkpoint等は別Gate |
| trendを素材として扱う余地 | trend grammarへ抽象化し、元素材の複製を禁止 |
