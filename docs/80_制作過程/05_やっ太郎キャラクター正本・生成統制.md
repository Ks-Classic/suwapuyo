## 1. 結論と品質の前提

いとこを長期に同一キャラクターとして運用することは可能である。ただし、プロンプト、reference画像、生成モデルの性能だけで完全同一性を保証することはできない。キャラクター同一性は次の多層防御で守る。

```text
作者承認済みCharacter Master
  ↓
媒体別変換ルール（2D / Live2D / 3D）
  ↓
固定Generation Package（reference + prompt + manifest）
  ↓
機械検査（寸法・色・構成・余計な要素）
  ↓
人の検査（作者・ブランド・制作）
  ↓
approved assetへ昇格
  ↓
公開・利用・学習結果
  ↓
必要な変更だけCharacter Change Requestへ戻す
```

「世界一の専門家100人全員が必ず感動する」は検証前に保証できない。本書では、その表現を目標品質として扱い、異なる専門領域から厳しくレビューされても説明・修正・再現できる状態を完了条件とする。人数や権威を仮装せず、実際のreviewer、日付、指摘、対応を記録する。

## 2. 用語

| 用語 | 定義 |
|---|---|
| Character Master | キャラの姿・構造・人格・利用条件を定める唯一の正本 |
| Canon | 作者・ブランド責任者が正式採用した設定・造形・資産 |
| Observed | 現行候補画像から見えるが、まだcanonと確定していない特徴 |
| Invariant | どの媒体・ポーズでも変更してはいけない識別要素 |
| Flex | 状況に応じて変えてよいが範囲が定義された要素 |
| Variant | 衣装、季節、年齢表現等、承認された別version |
| Derivative | 公式masterを基に作られた2D、Live2D、3D、AI生成物 |
| Golden Set | 同一性・品質を比較する作者承認済み基準画像群 |
| Generation Package | 生成時に使うreference、prompt、設定、禁止事項、manifestの一式 |
| Drift | 世代・媒体・修正を重ねるうちに、識別要素や人格がずれること |
| Promotion | draftをreviewedまたはapprovedへ昇格する操作 |
| Revocation | 権利・品質・事故により、承認済み資産の利用を停止する操作 |

## 3. 正本の優先順位

矛盾した場合は上位を優先する。

1. 作者・ブランド責任者が署名した利用契約・権利範囲
2. `cousin-character-master.json`の最新approved major/minor version
3. 作者承認済み2D turnaround・construction sheet
4. 作者承認済みGolden Set
5. Live2D source / Blender source / VRM等の媒体別master
6. approved derivative asset
7. reviewed draft
8. AI生成候補、会話、prompt、未承認画像

AI生成画像、3D render、SNSで反応が良かった画像を理由に、上位masterを黙って変更してはいけない。反応を設定へ反映する場合はCharacter Change Requestを発行する。

## 4. 現行候補v0.1の観測と未確定点

参照候補:

- `public/content/04_ツナやす_ブランド/01_キャラクター案/yasu-cousin-draft-v1.png`
- `public/content/04_ツナやす_ブランド/01_キャラクター案/yasu-cousin-transparent-v1.png`

観測できる特徴:

- サンゴ〜オレンジ系の丸い爬虫類・ヤモリ／若いトカゲ系。
- 大きな丸い頭、短い胴、独立して動かせる腕・脚、長い尾。
- 額中央に大きな葉／鱗型1つ、左右下に小型2つの計3記号。
- 大きい黒目、白いhighlight、桃色の頬、鼻孔、開いた笑い口、牙1本。
- 顎から腹、尾の下面にクリーム色領域。
- 黄色い前開きベスト、青緑の円形badge。
- 黒〜濃灰の太い外形線、角の少ない丸い造形、柔らかい陰影。
- 片方の眉を上げた、無鉄砲で自信のある表情。
- やすキャラと共通する爬虫類、頬、黒目、腹側の明色を持ちながら、色、頭形、服、額記号、手足、尾で区別できる。

未確定であり、作者が決める項目:

- 正式な動物種、性別表現、年齢感、身長・体格。
- 正面neutral時の頭形。現行画像の右上の膨らみが恒久形状か、髪・頬・ポーズ表現か。
- 手指・足趾の本数と、肉球／吸着padの配置。現行画像だけでは左右で見え方が一定しない。
- 眉が片側だけなのか、反対側は省略表現なのか。
- 牙の本数・左右・閉口時の見え方。
- 額3記号の正確な形、比率、間隔、回転、横・後ろからの見え方。
- ベストの背面、襟、縫製、badgeの正式意味・位置・色。
- 腹側cream領域の境界と、尾先まで続くか。
- gradient・影・highlightが公式画風か、生成案固有の表現か。
- 公式配色値、印刷CMYK、単色・小サイズ時の代替。
- やすキャラとの身長差、家系関係、世界内での立場。

これらをAIや実装者が推測で決めない。正式確定までは`observed`として扱い、外部制作の固定仕様にしない。

## 5. Identity Lockの階層

### Tier 0: 権利・作者・名称

変更には契約・権利者確認が必要。

- 作者、著作権者、利用許諾者、監修者
- 正式名称、別名、表記、商標確認
- AI入力、生成、学習、3D、Live2D、動画、商品化、広告、再許諾
- 利用期間、地域、媒体、終了・削除条件

### Tier 1: 識別DNA

major version変更と作者承認が必要。

- 種・基本silhouette・頭身
- 頭形、目、頬、鼻、口、牙、額記号
- 基本色、腹側領域、尾、手足
- 固有衣装とbadge
- 公式やすとの共通点・相違点

### Tier 2: Construction

minor version変更と作者またはdesign supervisor承認が必要。

- 頭・胴・手足・尾の寸法比
- 目・頬・口・額記号の配置grid
- 指・趾、関節、可動域
- 線幅、角丸、重なり、outline処理
- 正面・横・後ろの整合

### Tier 3: Expression / Motion Grammar

承認済み範囲内ならpatch versionで追加できる。

- 表情、口形、目形、眉、頬
- 走る、踊る、転ぶ、座る、指さす等
- cartoon exaggerationの上限
- しっぽ、ベスト、頬のsecondary motion

### Tier 4: Wardrobe / Props / Scene

campaign単位で変更可能。ただし識別DNAを隠さない。

- 季節衣装、小物、帽子、イベント装飾
- 背景、lighting、画材、camera
- 字幕、frame、スタンプ

### Tier 5: Experimental

公開時に実験と識別し、公式masterへ自動昇格しない。

- AIによる大胆な画風変換
- パロディ的演出
- 極端な変形、着ぐるみ、ロボット化
- 生成動画のtemporal deformation

## 7. 2D Construction Sheet要件

### 7.1 Turnaround

最低限、同じneutral poseと同じscaleで次を描く。

- 正面
- 左右3/4
- 左右側面
- 背面
- 上面参考
- 下面参考

各viewで頭頂、目線、顎、肩、腰、膝、足裏を共通guideへ揃える。横・後ろが存在しない状態で、AIや3D制作者に背面を創作させない。

### 7.2 比率

絶対pixelではなく、頭幅または全高を基準に比率で定義する。

```text
overall_height = 1.000
head_width / overall_height = author_to_define
head_height / overall_height = author_to_define
eye_center_y / head_height = author_to_define
body_width / head_width = author_to_define
arm_length / overall_height = author_to_define
leg_length / overall_height = author_to_define
tail_length / overall_height = author_to_define
```

許容差を用途別に持つ。

| 用途 | 寸法許容差 | 備考 |
|---|---:|---|
| official key visual | ±2% | 作者監修 |
| standard SNS illustration | ±4% | foreshortening補正を除く |
| animation smear frame | 定量外 | 前後frameで公式形へ戻る |
| chibi variant | variant定義 | 通常版と混同しない |
| merchandise dieline | ±1% | 印刷・成型仕様を優先 |

数値はturnaround確定後に計測し、作者が見た目を確認してapprovedにする。現行draftから自動算出した値をcanonにしない。

### 7.3 顔

face constructionに次を固定する。

- eye outer shape、左右距離、highlightの個数・位置
- cheek shape、色、eyeとの距離
- nostril shape・間隔
- mouth corner、口内、舌、牙
- browの本数、太さ、基準角度
- forehead markのanchorと比率
- neutral、blink、closed mouthでの残存要素

目、頬、額記号の三つを一次識別要素として、cropや小サイズでも同時に二つ以上が残るようにする。

### 7.4 手・足・尾

現行案で最もdriftしやすい領域として独立sheetを作る。

- 手指の正式本数、親指相当、padの数・形・色
- 足趾の正式本数、踵、足裏pad
- 正面・背面・握る・指す・ピース・手を開く
- 尾の付け根、断面、先端、腹側色、曲がる方向
- 尾が体の前後どちらを通るかのocclusion rule
- 手足を人間化しすぎない関節・爪・指長の上限

### 7.5 衣装

- ベストの前・横・後ろ、襟、裾、内側、留め具
- badgeの形、位置、意味、回転可否
- 動いた時の開き、座った時の重なり
- 衣装なしvariantの可否
- 季節衣装が公式ベストを覆う場合の識別badge代替

## 8. Palette・線・陰影

### 8.1 色

色はsRGB HEXだけでなく、RGB、CMYK参考、CIELAB参考、用途を定義する。

```ts
type CanonicalColor = {
  id: string;
  name: string;
  role: 'body' | 'belly' | 'mark' | 'cheek' | 'eye' | 'mouth' | 'outfit' | 'badge' | 'outline';
  srgbHex: string;
  lab: [number, number, number];
  cmykReference?: [number, number, number, number];
  toleranceDeltaE2000: number;
  allowGradient: boolean;
};
```

screen、印刷、暗背景、色覚多様性、grayscaleで識別できることを確認する。生成画像の照明色を公式body colorとして再採取しない。

### 8.2 線

- 基準canvasに対する外形線・内線の比率
- line cap、join、角の丸み
- 外形線と顔パーツ線の強弱
- 小サイズ時に省略できる内線
- 影側でもoutlineを黒く潰しすぎないrule
- 3D toon outlineと2D線幅の見え方対応

### 8.3 陰影

flat canon、standard shaded、special lightingの3presetを分ける。

- flat canon: 色確認・turnaround・商品仕様の正本
- standard shaded: SNS通常絵。光源方向と影色を固定
- special lighting: scene依存。body colorを変えず、環境光として処理

## 9. Expression Atlas

最低24表情を作り、顔だけでなく全身gestureとしっぽも定義する。

| Group | 表情 |
|---|---|
| neutral | neutral、listening、thinking |
| positive | happy、proud、excited、relieved、moved |
| comic | oops、caught、panic、blank、overconfident、反省3秒 |
| negative-safe | sad-lite、frustrated-lite、worried、sorry |
| action | determined、surprised、running-focus、dance-focus |
| meta | camera-aware、author-aware、prompt-confused |

禁止:

- 他者への侮蔑、差別、暴力を楽しむ表情
- 子ども向け文脈で強すぎる恐怖・流血・性的表現
- 医療・健康効果を断定する権威的表情
- 失敗を反省せず他者のせいにする表情・台詞

`angry`は他者攻撃ではなく「課題に負けたくない」「自分の失敗へ悔しい」へ限定する。

## 10. Pose・Motion Grammar

### 10.1 基本pose atlas

最低32pose:

- stand neutral、sit、crouch、lie、sleep
- walk、run、stop、turn、jump、land、trip、recover
- wave、point、clap、think、explain、apologize
- dance step、spin、pose、off-beat、success
- type、draw、hold phone、film、meet、present
- look at camera、look outside frame、meta peek

### 10.2 Exaggeration

- squash/stretchはbody全体比率の範囲を定義する。
- smearは中間frameだけで使い、静止key visualへ流用しない。
- 眼球・口・牙・指・尾を増殖させない。
- 驚きで額記号やbadgeを飛ばさない。飛ばすなら非canon effect layerにする。
- 服・尾の遅れはsecondary motionとし、身体本体の位置を上書きしない。

### 10.3 Character behavior ratio

初期運用:

```text
成功・前進 60%
愛嬌ある小失敗 30%
大きな実験 10%
```

同じ失敗を繰り返さない。`failure_id → lesson → changed_behavior`を記録し、成長を人格canonの一部にする。

## 11. Live2D Master

2D静止画masterをそのまま切り刻まず、作者監修で可動用sourceを作る。

必須layer:

- head base、forehead marks、eyes L/R、highlights、brows L/R
- cheeks、nose、mouth outer、mouth inside、tongue、fang
- neck/body、belly、arms upper/lower L/R、hands variants
- legs upper/lower L/R、feet variants
- vest front/back/flaps、badge
- tail segments、tail underside
- shadow/highlightをbody partと分離

必須parameter:

- ParamAngleX/Y/Z
- ParamBodyAngleX/Y/Z
- ParamEyeLOpen / ParamEyeROpen
- ParamEyeBallX/Y
- ParamBrowLY/RY/Angle/Form
- ParamMouthOpenY / ParamMouthForm
- ParamArm/Hand/Leg pose
- ParamTailX/Y/Wave
- ParamVestFlap
- expression preset

Live2Dで不可能または不自然な全身ダンスを無理に一modelへ入れない。会話・顔・上半身はLive2D、全身ダンスは3D VRMまたはframe animationへroutingする。

## 12. 3D Masterとの整合

2Dと3Dは相互変換の正本にせず、共通Character Masterから派生する兄弟assetとする。

2D→3D mappingで決める:

- 正面shapeを保ったまま横から成立する頭volume
- 眼球を球体にするか、平面toon eyeにするか
- 額記号をtexture、geometry、decalのどれにするか
- 口・牙・舌の立体と閉口
- 手足の関節とpad
- 尾の骨数、物理、接触
- vestの厚み、裏面、cloth physics
- outline、MToon、影、camera FOV

3D renderを2Dの新しい正面masterとして採用しない。2Dと3Dで見え方が衝突したら、作者が共通constructionを変更するか、媒体別許容差として記録する。

## 13. GPT Image 2 Generation Package

OpenAI公式のGPT Image 2 prompting guideは、production workflowで次を推奨している。

- promptをscene → subject → details → constraintsの一定順で書く。
- multi-image入力をindexと役割で明示する。
- change-onlyとpreserve-listを毎回明記する。
- 一度に多くを変えず、小さい単一変更で反復する。
- identity-sensitive editはmedium/highを比較する。

本プロジェクトはこれを最低基準とし、さらに次を固定する。

### 13.1 Reference slots

| Slot | 内容 | 必須 |
|---|---|---:|
| Image 1 | approved neutral-front identity anchor | 必須 |
| Image 2 | approved turnaround / construction | 必須 |
| Image 3 | approved expressionまたはpose reference | 用途別 |
| Image 4 | approved palette / line / shading sheet | 必須 |
| Image 5 | scene/layout reference。キャラreferenceではない | 任意 |

生成済みoutputを次のidentity anchorにしない。approved assetへ昇格した場合も、Image 1・2はoriginal masterを維持する。

### 13.2 Prompt template

```text
[INTENDED USE]
Medium, platform, dimensions, audience, public/draft status.

[SCENE]
Background, camera, framing, lighting, negative space.

[CHARACTER IDENTITY]
Use the exact same character defined by Image 1 and Image 2.
Image 1 is the primary identity anchor.
Image 2 defines anatomy, proportions, markings, costume construction, and rear/side geometry.
Image 3 defines only the requested expression/pose.
Image 4 defines only palette, line weight, and shading.

[REQUESTED CHANGE]
Change only: {single change}.

[HARD INVARIANTS]
Preserve exact species, silhouette, head-body ratio, face geometry,
forehead marks, eye/highlight structure, cheek placement, fang count/side,
digit/pad count, belly boundary, vest construction, badge, tail shape,
palette, line language, and personality.

[POSE AND OCCLUSION]
Full body/close-up, feet/hands visible as required, gaze, contact points,
which limb is in front, tail route, object interaction.

[DO NOT — no-text asset]
No redesign, no new accessories, no extra digits, no missing markings,
no species change, no humanized anatomy, no text, no logo, no watermark,
no signature, no unrelated character, no style drift.

[OUTPUT]
One composition. Opaque or transparent requirement. No contact sheet unless requested.
```

promptの`fang count/side`等はmaster確定後に実値へ展開する。未確定変数を曖昧なまま生成へ送らない。

### 13.2A Image Typography Rule

SNSの一枚広告・ポスター・カルーセル等、文字を含む画像は、**原則として文字も含めてGPT Image 2で一体生成する**。採用後に別ツールで文字だけを手組み・合成して完成させない。

- 文字ありassetでは`[DO NOT — no-text asset]`の`no text`を、指定した`Text (verbatim)`以外の文字を禁止する、へ読み替える。
- promptに文字列、改行、句読点、配置、階層を明示する。曖昧な「それっぽいコピー」は渡さない。
- 生成後にOCRと人の目で、表記、句読点、改行、可読性、余計な文字を確認する。
- 指定文字が崩れた場合は手組みで直さず、GPT Image 2で再生成する。
- 法令表示、アクセシビリティ上の代替テキスト、リンク先のHTML本文、字幕、媒体ネイティブの投稿文は画像内文字ではないため、この制約の対象外とする。
- 例外を作る場合は、木幡さんが理由・対象asset・期限を記録して承認する。

### 13.3 Iteration protocol

1. 新規sceneはapproved anchorから開始。
2. 1回のeditで変更する主目的は1つ。
3. 各iterationでHard Invariants全文を再指定。
4. failureを`prompt failure / model limitation / reference defect / master ambiguity`に分類。
5. 3回同じfailureが出たらpromptを長くせず、referenceまたは手作業工程を変更。
6. 手、足、額記号、衣装、文字は高risk cropとして別確認。
7. 最終公開assetは人が補正してよい。補正sourceと担当をmanifestへ記録。

### 13.4 Reproducibility manifest

全生成で保存:

実装開始値は[`キャラクターシステム/やっ太郎生成記録_雛形.json`](./キャラクターシステム/やっ太郎生成記録_雛形.json)を複製し、`REPLACE-*`、仮hash、仮dimensionを実値へ置換する。template自体は生成実績・承認証跡として扱わない。

- asset ID、generation ID、日時、担当
- model ID、利用surface、quality、size、background
- full prompt、prompt template version
- input asset ID・version・SHA-256・役割
- output SHA-256
- edit chain。ただし未承認outputをidentity anchorにしない
- review score、hard failure、修正、承認者
- rights 証拠、公開可否、削除期限

seed等、providerが保証しない値を再現性の根拠にしない。model側更新で同じpromptの結果が変わり得る前提でGolden Set regressionを行う。

## 15. QA Architecture

### 15.1 Hard Gate

一つでも失敗したらscoreに関係なく公開不可。

- rights・AI入力・商用・媒体許可が確認済み
- approved master versionが特定できる
- 額記号、目、頬、牙、指・趾、腹、服、badge、尾がmasterと整合
- 余計なlogo、未指定文字、watermark、署名、第三者キャラがない。文字ありassetでは指定したverbatim textが正確
- 手足の欠損・増殖、逆関節、重大な貫通がない
- 差別、性的、過度な暴力、医療断定、他者攻撃がない
- 子ども・個人情報・未許諾人物referenceを含まない
- sourceとmanifestが追跡できる

### 15.2 100点rubric

| 領域 | 点 |
|---|---:|
| Identity DNA | 25 |
| Construction・anatomy | 15 |
| Face・expression | 10 |
| Hands・feet・tail・costume | 10 |
| Palette・line・shading | 10 |
| Character behavior・story fit | 10 |
| Composition・readability | 8 |
| Cross-media adaptability | 5 |
| Rights・provenance completeness | 5 |
| Accessibility・production readiness | 2 |

公開候補は95点以上、hard failure 0を目安とする。点数は作者承認の代替ではない。master変更は100点でも作者承認が必要。

### 15.3 機械検査

機械検査の候補:

- file format、dimension、alpha、color profile、size、hash
- contour bounding boxと主要比率
- palette samplingとDelta E
- 額記号maskの個数・位置・面積
- 顔landmark相対位置
- 手足・尾のvisibility inventory
- outline thickness sampling
- OCRで不要文字検出
- perceptual hashで重複・世代追跡
- transparent edge halo
- NSFW・logo候補等のsafety補助

機械判定だけで`同じキャラ`と確定しない。stylized anatomy、occlusion、emotion、personalityは人が判断する。

### 15.4 人のreview

最低3role:

1. Author/Design: キャラそのもの、造形、画風
2. Brand/Product: 人格、物語、目的、公式やすとの差
3. Production/Rights: 媒体、権利、ファイル、再利用、公開条件

high-risk用途では、animation、3D、accessibility、legal/privacy、marketingのreviewerを追加する。

## 16. Golden SetとStress Test

最低12条件を作者承認する。

| ID | 条件 | 主な検証 |
|---|---|---|
| GS-001 | neutral front | identity基準 |
| GS-002 | side/back | 未見geometry |
| GS-003 | close-up emotion | 顔・額・牙 |
| GS-004 | full-body run | 比率・接地 |
| GS-005 | dance foreshortening | 手足・occlusion |
| GS-006 | sit/crouch | 腹・服・尾 |
| GS-007 | holding phone | 指・接触 |
| GS-008 | officialやすと並ぶ | 親戚感と非誤認 |
| GS-009 | dark background | outline・palette |
| GS-010 | 32px circle crop | 小サイズ識別 |
| GS-011 | monochrome/print | production |
| GS-012 | meta comic scene | 人格・台詞 |

model、prompt template、reference、master major/minorを変更する前後で同じ12条件を生成・比較する。hard failure増加、平均score低下、作者の違和感があればupgradeをholdする。

### 16.1 Training / Golden / Holdoutの分離

- `Training Pack`: LoRAやcustom modelを作る場合だけ学習へ使用する作者承認済みasset。caption、crop、hash、外部送信・weight配布条件を持つ。
- `Golden Set`: 回帰比較専用。学習へ混ぜず、同じ条件でmodel / prompt / referenceの変更前後を測る。
- `Holdout Stress Set`: promptや学習の調整担当が最終評価まで見ない。未知のpose、occlusion、照明、背景、motionで過学習を検出する。

同じ画像群を学習、調整、最終合格判定の全てへ使用してはならない。`Golden Setで高得点`だけでは、未知sceneの同一性を証明しない。

## 17. Blind Recognition Test

主観を補うため、一般参加者へ次を試す。

- 公式やす、いとこ、他キャラを混ぜ、1秒・3秒で同一人物判定
- いとこの異なるpose・画風を見せ、同じキャラか確認
- 公式やす本人と誤認しないか確認
- 性格語を自由回答し、狙う人格との一致を測る

初期目標:

- 3秒同一キャラ認識90%以上
- 公式やすとの誤認5%未満
- `やんちゃ / 好奇心 / 愛嬌 / 前向き`のいずれか想起70%以上
- `怖い / 攻撃的 / 信用できない`の意図しない想起10%未満

母数、対象、提示順、画像、集計を記録する。目標未達を隠さず、どの識別要素を直したかをprocess recordにする。

## 18. Asset Lifecycle

```text
concept
  → generated-draft
  → selected-draft
  → reviewed
  → approved
  → published
  → deprecated
  → revoked
```

- generated-draft: 外部公開不可
- selected-draft: 比較・内部検討可
- reviewed: 指摘対応中。公式と表記しない
- approved: 指定用途・期間だけ利用可
- published: URL・日時・variantを記録
- deprecated: 新規利用停止。既存利用の扱いを明記
- revoked: 公開停止・削除・差替えを実行

approved assetを直接上書きしない。修正は新asset IDまたはversionを作り、旧版を保持・deprecatedにする。

## 19. Versioning

Character Masterはsemantic versioningを使う。

- MAJOR: 種、silhouette、顔、基本衣装等のIdentity DNA変更
- MINOR: construction、正式palette、表情・可動の拡張
- PATCH: 誤記、metadata、既存意図を変えない補正

各assetは`character-master-version`と`asset-version`を両方持つ。

```text
cousin-master 1.2.0
asset COUSIN-ILLUST-0042 v3
prompt-template 2.1.0
model gpt-image-2
```

## 20. Character Change Request

変更申請に必須:

- change ID、提案者、日時、理由
- 対象tierとversion
- 利用者・ブランド・2D・Live2D・3D・商品への影響
- before/after
- 権利者・作者への影響
- Golden Set regression
- migration対象asset
- rollback方法
- 承認者と決定

SNSの反応が良い、AIが毎回そう描く、3Dで作りやすい、という理由だけで変更を確定しない。ブランド意図と長期資産価値を評価する。

## 21. Rights・Privacy・Security

確定する権利:

- 2D原画、設定、名称、3D、Live2D、motion、voiceの著作権・利用権
- AI serviceへのreference入力
- AI outputの採否・修正・商用・広告・商品化
- 外部creatorへのreference共有・再許諾
- training、fine-tuning、LoRA、embedding、dataset化
- 終了時のsource、公開物、SNS、学習物、商品在庫の扱い

運用:

- reference packageに個人情報、secret、未許諾第三者素材を入れない。
- providerへ入力する前に、現行terms、data controls、保持・学習方針を利用surfaceと契約単位で確認する。
- API、ChatGPT、Codex、外部生成serviceを同じdata boundaryと仮定しない。
- 未公開masterへaccess control、least privilege、download logを設定する。
- 外注終了、端末紛失、アカウント侵害時のaccess revokeを用意する。
- 公開PNGだけからsource、layer、3D modelを無制限再配布できるとは扱わない。
- code、workflow engine、custom node、base model、checkpoint、LoRA/adapter、input、outputのlicenseを別々に台帳化する。repository本体がOSSであることだけを商用可否の根拠にしない。
- C2PA / Content Credentialsが付く場合も、SNSや再encodeで失われ得るため、内部manifest、input/output hash、review、rollback pointerを正本として保持する。

## 22. Incident Response

対象:

- 誤キャラ・権利侵害・未許諾素材・個人情報・不適切表現・AI表示漏れ
- 公式やすとの誤認
- providerやplatformの規約変更
- master/source流出

手順:

1. 新規公開・予約投稿を停止。
2. incident ID、URL、asset ID、master version、影響範囲を記録。
3. 公開停止・差替え・削除の優先度を決定。
4. 権利者・作者・運営へ連絡。
5. 訂正が必要なら、何が違い、どう直したかを明確に出す。
6. derived asset、予約投稿、広告、商品、cacheを検索。
7. 原因をprompt、人、master曖昧、tool、権限、review漏れに分類。
8. Gateを修正し、Golden Set regression後に再開。

## 23. Reviewer Matrix

「100人基準」を次の10視点へ分解し、各視点で致命傷がない状態を目指す。

| 視点 | 問い |
|---|---|
| Character designer | 形・色・線・差別化が説明できるか |
| Brand strategist | 長期で認知・信頼・展開性があるか |
| Animator | 動かしても破綻せず感情が伝わるか |
| Live2D rigger | layer・parameter・occlusionが成立するか |
| 3D technical artist | 横・後ろ・関節・materialが定義されているか |
| AI creative engineer | reference・prompt・eval・rollbackが再現可能か |
| UI/visual designer | 小サイズ、crop、背景、文字と共存するか |
| Marketer/PdM | 投稿が目的・物語・指標へつながるか |
| Legal/privacy | 権利・同意・data boundary・削除が追えるか |
| Production operator | 誰でも迷わず制作・review・復旧できるか |

各視点を複数人に依頼する場合も、単なる好み投票ではなく、rubricと具体的指摘を残す。
