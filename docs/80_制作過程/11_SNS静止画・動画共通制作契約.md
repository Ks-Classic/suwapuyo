# SNS静止画・動画 共通制作契約

> 責務: 1つの企画から静止画と動画を派生するときの、媒体に依存しない正本と公開Gate
> 適用先: `.agents/skills/suwapuyo-SNS-image/`、`.agents/skills/suwapuyo-SNS-video/`

## 1. 基本方針

静止画と動画は同じ企画契約を共有するが、別成果物として検品・承認する。静止画の承認を動画へ、動画の承認を静止画へ自動継承しない。

旧Shorts Studioの画面や固定候補は正本にしない。制作UIを将来作る場合も、本書の契約、各媒体Skill、asset-registerを読み書きする補助画面とする。

動画で動かす・踊らせる・生成実験する主役は基本`やっ太郎`とする。`じく太郎`は保護原画不変の別Gateとし、やっ太郎の実験対象へ含めない。

## 2. 共通契約

企画ごとの`コンテンツ/social/posts/<コンテンツ-id>/post.md`に、生成前に次を固定する。

| 項目 | 必須内容 |
|---|---|
| 識別 | コンテンツ ID、version、親企画ID |
| 意図 | 目的、対象、伝えること、見た人にしてほしい行動 |
| 正本 | 画像内コピー、動画台本、投稿本文。未確定部分を明記 |
| 事実 | 事実主張、出典、確認者。健康・効果・売上を推測しない |
| キャラ | asset ID、Character Master version、許諾証拠、許可された変形 |
| 派生 | static / carousel / short、媒体、寸法、crop条件 |
| 承認 | 内容、権利・造形、公開の承認者 |
| 状態 | review / approved / published / rejected |

静止画と動画で同じ主張・名称・CTAを使う場合は、この契約を共通正本にする。媒体別に短縮するときは、変更後のコピーまたは台本も同じ`post.md`へ記録する。

## 3. 共通Hard Gate

次のいずれかが未確認なら`review`から進めない。

1. secret、個人情報、未許諾の人物・会話・出展者情報を含まない。
2. キャラ、画像、ロゴ、音源、フォント、振付の利用範囲と出典を確認できる。
3. 診断、治療、効果保証、不安をあおる健康表現を含まない。
4. 名前、商品名、日付、CTA、字幕、画像内コピーが正本と一致する。
5. キャラの造形・性格・関係性が承認済み正本の範囲内である。
6. crop後も意味、顔、文字、CTAが欠けず、実機相当で読める。
7. 人が内容、権利・造形、公開可否を確認している。

`公式やす／じく太郎`は媒体別の利用範囲が記録されるまで動画へ使用しない。静止画では登録済み保護原画だけを、専用Skillのhash・pixel検査を通して使用する。動画化、口パク、移動、変形、AI入力を静止画の許諾から推定しない。

`やっ太郎`は2D、rig、3D、motion retarget、動画生成AI、最新OSS・動画ツールの比較実験対象にできる。ただしCharacter Master、入力権利、tool/modelの利用条件、review Gateを通し、未承認出力を新しい正本へ自動昇格させない。

## 4. 媒体固有ルール

| 領域 | 静止画・カルーセル | ショート動画 |
|---|---|---|
| 実装Skill | `suwapuyo-SNS-image` | `suwapuyo-SNS-video` |
| 基準寸法 | 1080×1350 | 1080×1920 |
| 文字 | GPT Image 2で完成画面と一体生成し、独立転記で照合 | 正本台本から決定的に描画し、字幕・音声・タイミングを照合 |
| 主な追加Gate | 4:5、文字完全一致、保護原画pixel一致 | 9:16、一覧crop、音ズレ、黒frame、字幕切れ、音源権利 |

文字の正確性は共通要件だが、生成方法は媒体固有とする。静止画の「ローカル文字後載せ禁止」を動画字幕へ適用しない。

## 5. 派生フロー

```text
共通post.md
  ├─ expected-copy.txt ─→ suwapuyo-SNS-image ─→ 静止画review
  └─ video brief/spec  ─→ suwapuyo-SNS-video ─→ 動画review
             ↓                       ↓
        媒体別検品                 媒体別検品
             └──────── 人の公開承認 ────────┘
                              ↓
                 asset-register / published記録
```

同じ修正が両媒体へ影響する場合は、先に`post.md`を更新し、その後に両成果物を再生成・再検品する。片方の生成物をもう片方の正本にしない。

## 6. 状態

- `review`: 自動検査済みでも人の承認前。投稿禁止。
- `approved`: 指定した媒体・versionだけ公開可能。
- `published`: 実際の投稿URL、日時、媒体、使用ファイルhashを記録済み。
- `rejected`: 公開、再利用、次世代生成の参照に使用しない。

完成報告では、静止画・動画ごとに生成結果、検証結果、未確認事項、保存先、公開状態を分ける。
