# すわぷよ・ふわふわランド境界再編

> 日付: 2026-07-21
> 状態: 完了（ローカル実装・検証済み、外部反映なし）
> 対象タスク: SUW-33 / TB-51

## 1. 誰の、何の課題を、どう変えるか

木幡さんが、すわぷよ本体・ふわふわランド・両者の接続・YourTIME当日運用・ブランド制作の現在地と次の手を、互いに混同せず即判断できる状態へ変える。

## 2. 修正前の事実

- 統合仕様の実装状態表が、すわぷよ本体とふわふわランドを同じ粒度で並べていた。
- Taskboardの`suwapuyo.tasks`には、アプリ、ランド、認証、会場調整、SNS、VTuber、事業条件がフラットに並んでいた。
- `src/App.tsx`ではURLで本体を分岐しているが、所有権を表す型付き契約はなかった。
- すわぷよ側のキャラ設定が、ふわふわランド内部の`renderer/sampleCharacters`を直接参照していた。
- QR claimは接続機能だが、すわぷよ本体とランド本体の内部実装を横断していた。
- その結果、「アプリはどこまで進んだか」という質問にランド側の完成度が混ざった。

## 3. Work contract

### 対象

1. 全体サマリーをポートフォリオ判定へ限定する。
2. 5領域の実装状態SSoTを分離する。
3. Taskboardへ可変workstream階層を追加し、すわぷよをpilot移行する。
4. コードへルート所有権、共有キャラ、接続契約の境界を導入する。
5. 構造化された評価証拠とhandoffを残す。

### 非対象

- Supabase migrationの適用。
- Cloudflare Access、LINE、LIFFの本番設定変更。
- 本番deploy、commit、push。
- 既存機能のUIデザイン変更。
- すわぷよとふわふわランドの別リポジトリ化・別deploy化。

### 変更可能範囲

- `docs/70_すわぷよ・ユアタイム統合仕様/`
- 本記録と評価証拠。
- Taskboardのschema、validator、表示、すわぷよpilotデータ。
- 挙動を変えないコード境界とそのテスト。

## 4. Hard threshold

一項目でも未達なら完了にしない。

| ID | 合格条件 |
|---|---|
| B-01 | 5領域の責務、URL、データ、利用者、非対象が一意である |
| B-02 | 各領域だけを読んで「実装済み・未完・本番可否・次のGate」を答えられる |
| B-03 | 接続機能がなくても、すわぷよ本体とランド本体が単独で動ける契約になっている |
| B-04 | Taskboardの階層なし既存プロジェクトが無変更で検証・表示できる |
| B-05 | node ID重複、参照切れ、深度超過、task重複所属をvalidatorが拒否する |
| B-06 | blocked / waiting_humanの重大Gateを上位集約が平均で隠さない |
| B-07 | 既存公開URLの振分けとテストが変わらない |
| B-08 | すわぷよ本体から`fuwafuwa-land`内部への新規直接依存を作らない |
| B-09 | TypeScript型検査、unit test、build、lint、`git diff --check`が通る |
| B-10 | 本番・DB・外部SaaSへ書き込んでいない |

## 5. 評価方法

- Builderレビュー: 差分単位で責務、重複、命名、参照切れを確認する。
- 機械評価: JSON parse、Taskboard validator、境界unit test、プロジェクトtest/build/lint。
- Evaluatorレビュー: 実装意図を脇に置き、質問への回答可能性、重大Gateの露出、後方互換、失敗時の分離を再判定する。
- 評価結果は`05_テスト/証拠/2026-07-21_プロダクト境界再編評価.json`を正とする。

## 6. 停止条件

- 既存未コミット変更と同じ行・同じ責務へ衝突する。
- Taskboardの既存7プロジェクトが後方互換を維持できない。
- DB、本番、外部SaaS変更が必要になる。
- キャラ所有単位など、外部仕様の未確定Gateがコード挙動を左右する。
