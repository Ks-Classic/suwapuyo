# じく太郎透過保護原画・validator修正記録

## 1. 何が起きたか

| 操作 | 期待 | 実結果 | 一次情報 |
|---|---|---|---|
| 透過保護原画をv3へ合成 | 不透明領域のpixel一致を検査 | 合成成功後、validatorが`TypeError`で停止 | `Image.getbbox() takes 1 positional argument but 2 were given` |
| validator修正後にv3を再検査 | 全Gate通過 | pass | size、copy、source hash、binary alpha、visible pixelsがすべて合格 |
| 従来JPG版v2を回帰検査 | 既存入力も合格 | pass | 同じvalidatorでv2も合格 |

## 2. 仕様上はどう動くべきだったか

```text
保管原本のhash確認
-> 外周白背景だけを二値透過
-> 透過原画のhash固定
-> 1:1合成
-> 不透明領域のpixel一致検査
```

## 3. 実際はどう動いたか

透過原画作成と1:1合成は成功したが、差分画像にalpha maskを渡すAPIを誤り、合否判定前にvalidatorが例外終了した。

## 4. 直接原因

- 確認済み: Pillowの`Image.getbbox()`はmask引数を受け取らない。
- 未確定: なし。

## 5. 根本原因

- 実装時にPillow APIの実呼び出しを最小fixtureで先に確認しなかった。
- 透過保護原画を扱うvalidatorの回帰ケースが存在しなかった。

## 7. 次からどう進めるべきだったか

1. 許諾範囲を「背景透過のみ」と固定する。
2. 二値alphaの保護原画を作る。
3. RGB版とRGBA版のvalidatorを先に実行する。
4. 完成画像へ合成して公開Gateを確認する。

## 8. 再発防止

- 透過原画はalphaを0/255に限定し、中間alphaをfailにする。
- 差分へalpha maskを貼った結果のbboxで、不透明領域だけのpixel一致を判定する。
- RGB版とRGBA版の両方を回帰検査する。
- 新規Skillは作らず、既存`suwapuyo-SNS-image`へ許諾例外と検査手順を統合する。
