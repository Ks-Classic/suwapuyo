## 0. 一文サマリ

**「自分の絵に会いたい」でアプリを起動させ（ふわふわランド→すわぷよ）、遊ぶうちに未病体操と出展者紹介に触れさせ（すわぷよ）、その全部をLINE「村の案内所」という1つの器で前→当日→後につなぎ続ける（LINE）。インスタは入口の発信。**

## 1. 全体アーキテクチャ（誰が器で、何が流れるか）

```
                  ┌───────────────────────────────────────────────┐
   インスタ ───────►│   LINE「村の案内所」＝デジタル健康ハンドブック   │◄─── 各所QR
   (発信/告知)      │   前=告知 / 当日=マップ / 後=お便り・アンケート  │   (入口・ブース・
                  │   ＝すべての器・継続接点・データが貯まる場所       │    すわぷよ・チラシ)
                  └───┬───────────────┬───────────────┬───────────┘
                      │ 起動リンク      │ マップ/紹介     │ アンケート/お便り
                      ▼               ▼               ▼
   ┌───────────────────────┐   ┌──────────────────┐   ┌──────────────────┐
   │ すわぷよ (PWA・常設)     │   │ ふわふわランド(当日) │   │ つなやす自前DB      │
   │ 遊ぶほど健康/体操/解放   │   │ 絵を描く→村に登場    │   │ アンケート回答(同意) │
   │ 相棒=自分の絵/ロゴ紹介   │◄──┤ 相棒QR引換で持ち帰り │   │ →出展者へ還元       │
   └──────────┬────────────┘   └──────────────────┘   └──────────────────┘
              │ track() タップ/体操/送客
              ▼
        Supabase (artworks / display_characters / tap_events …)  ← 共有基盤
```

- **共有基盤＝Supabase**（同一リポ・同一プロジェクト）。ふわふわランドが描いた `artworks` を、すわぷよが相棒として読む。
- **器＝LINE**（薄いラッパー）。各PWAはLINEのリッチメニューから起動。
- **データの正本は2系統**：①体験/送客の事実値＝`tap_events`（匿名・集計）／②来場者の声・属性＝**つなやす自前同意DB**（要配慮個人情報、LINEとは分離）。

## 3. 全体導線（前→当日→後・データの動き付き）

### 3.1 開催前
1. **インスタ**で未病ショートを見て認知 → プロフィールから**すわぷよ**/LINEへ。
2. **すわぷよ**を遊ぶ（遊ぶほど健康）。体操カウントは**端末ローカル（匿名）**に貯まる。
3. すわぷよ内の節目・チラシ・インスタのQRから**LINE登録**。→ LINEで世界観発信・開催告知（PULL）。

### 3.2 当日（会場）
1. **ふわふわランド**でタブレットに絵を描く → 村にふわふわ登場（感動）。`artworks`にStorage保存（顔なし・名前任意）。
2. 描き終わると**相棒引換QR/コード**を発行（持ち帰り）。同じ場所に**LINE登録QR**も併置。
3. **当日マップ**（LINEミニ導線 or PWA）でキャラ/ロゴをタップ→ブース紹介（`07`のtap-popup）。`track()`で接点を記録。
4. ブース/入口の各所QRでLINE登録が進む（来場の起点）。

### 3.3 開催後（家）
1. 家で**すわぷよ**を再起動（動機＝**自分の絵=相棒に会いたい**）。相棒コードで`artworks`から自分の絵を取得→相棒として常駐。
2. 遊ぶ→体操を重ねる→**累計回数/継続日数/部位コンプ**で隠しキャラ解放（ツムツム的）。体操ごとに出展者紹介に触れる。
3. 解放の節目で**LINE/インスタ/次回YourTIME告知**へ送る。
4. **LINE**：未病tips・村のお便り・**アンケート**（自前フォーム→自前DB、出展者ごと同意）。回答特典＝GIVE。集めた声を**出展者に還元**（`09`レポート）。

## 4. つなぎ目（接続点）の設計＝本書の核

| # | 接続 | 入力 → 出力 | 技術 | 未決 |
|---|---|---|---|---|
| **C1** | ふわふわランド → すわぷよ（相棒） | 描いた`artwork.id` → 引換コード/QR → すわぷよで取得→相棒表示 | Supabase `artworks`＋IndexedDBキャッシュ（オフライン）。コード=短縮id or 専用引換コード | 短縮コード方式か生id か。`03`D-1/D-2 |
| **C2** | 各所 → LINE登録 | 入口/ブース/すわぷよ/チラシのQR → LINE友だち追加 | LINE公式URL/QR。登録は薄ラッパー | 来場検知をどこまで取るか（`09-line`L-2） |
| **C3** | すわぷよ → LINE/告知 | 解放イベント/タイトル → LINE登録・インスタ・YourTIME告知バナー | すわぷよ内リンク＋LINEリッチメニュー相互リンク | 送り口の出し方（PUSHにしない） |
| **C4** | 体験 → 計測 → 還元 | tap/体操/送客 `track()` → `tap_events`集計 → 出展者レポート | Supabase events＋AIサマリー（`09`）。SNSは手入力スナップショット | API連携は継続案件のみ（`09`§5） |
| **C5** | アンケート → 出展者 | 回答（同意付き）→ 自前DB → 同意した出展者へ | **自前同意フォーム**（LINE第三者提供は不可） | ツール選定・名寄せキー（任意メール） |

> **設計の肝**：C1（相棒）が起動動機、C4/C5（計測・アンケート）が課金の心臓。ここが弱いと全部が単発で終わる。

## 5. データ／アイデンティティ・モデル（3層）

| 層 | 持つもの | 場所 | 性質 |
|---|---|---|---|
| **L1 匿名ローカル** | 体操カウント・streak・解放・相棒id | 端末（localStorage/IndexedDB） | ログイン不要・個人を追跡しない。すわぷよの基本はここで完結 |
| **L2 LINE任意紐付け** | LINE友だち（村との継続接点） | LINE公式 | **エクスポート不可・第三者提供不可**（規約8.2）。集計のみ使う |
| **L3 自前同意DB** | アンケートの声・属性（要配慮個人情報） | つなやすDB | **自前同意フォームで取得**・出展者ごと同意・患者紹介料は取らない |

- **原則**：子ども体験にログイン要求を入れない（`09`§11.4）。個人追跡しない。L2とL3を混ぜない。
- **名寄せキー**：L3で申込メールを任意1項目だけ仕込む→将来Peatixチケットと突合（今回は使わない）。

## 6. 計測と還元の流れ（課金の心臓）

```
すわぷよ/ふわふわランドの行動
  └ track("tap"/"taisou_sponsor_view"/"cta_click", …)
       └ Supabase tap_events（匿名・集計）
            └ 出展者レポート（接点数＋AIサマリー＋次の一手）  ← 09
                 └ 「あなたのブースに◯人・こういう声」＝出展ROIの証拠
                      └ 特典×出展者課金（GIVEを載せる権利）＝露出を売らない形で収益
                           └ 収益が運営に還元（バケツC＝01§5.2）
```

- 8/2は**API連携を急がない**。`tap_events`＋手入力スナップショット＋定性メモ＋AIサマリーで「参加した価値」を返す（`09`§1）。
- 特典課金は**8/2は急がず、実績を握ってからPhase1で**売るのを推奨（`09-line`L-1）。

## 7. 全体を貫く原則・制約（破ると設計が崩れる）

1. **子どもの作品・遊びが主役**。案内・送客はその上に乗る。
2. **PULL であって PUSH ではない**（タップして開く・通知爆撃しない・週1上限）。
3. **「広告」と呼ばない**。村の案内／出展者を主役にする紹介。露出枠は売らない（特典＝GIVEを載せる権利は可）。
4. **オフライン耐性**（会場ネット不安定・広大＝`01`§9）。PWAローカル動作・相棒は引換後ローカル保持。
5. **医療広告ガード**（効果効能を断定しない・PR表記・出展者本人＋諏訪監修＝`01`§7/`04`）。
6. **個人情報は丁寧に**（L1/L2/L3分離・自前同意・要配慮）。
7. **運営メンバーへの還元が大義**（収益化の建て付け）。
