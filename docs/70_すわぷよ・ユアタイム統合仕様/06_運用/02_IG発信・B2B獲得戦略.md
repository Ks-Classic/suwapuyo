# IG発信・B2B獲得戦略

> 文書状態: 発信戦略・B2Bファネル構造の正本（投稿台本・カレンダー・キャラ口調ガイドは別文書）  
> 最終更新: 2026-07-11  
> 目的: 表は「かわいい・面白い」、裏は「最先端AI×マーケの実演」。最終目的は出展社・事業者からの個別案件獲得（決定-013）

## 1. 構造の一文

やすキャラが、親子には遊びを、事業者には「この裏側ぜんぶ、こう作ってこう回している」を見せる。**このアプリと運用自体が営業デモである。**

## 2. 二重オーディエンス

```text
表（B2C・親子）:
  パロディ / キャラ日常 / YourTIME案内 / 未病レベルの生活ヒント
      ↓ リーチと好感を作る

裏（B2B・事業者）:
  制作裏側 / AI活用の実演 / 計測とレポートの中身
      ↓ 信頼と案件を作る
```

- 同一アカウントで両方を出す。B2C投稿がリーチとアルゴリズム学習を担い、B2B投稿が信頼と相談を生む。
- 裏側解説もやすキャラの声で出す。「かわいく、でも中身はガチ」を崩さない。専門用語は使ってよいが、煽り文体は使わない。

## 3. コンテンツ柱（`01_デモ・LINE・Instagram運用.md` §5を継承・具体化）

| 柱 | 表の顔 | 裏の狙い |
|---|---|---|
| 1. キャラ日常・パロディ | 笑い・保存・シェア | リーチ獲得・アルゴリズム学習 |
| 2. AI実演 | 「これ、AIで作りました」 | 技術力の証明 → B2B興味の入口 |
| 3. 制作裏側 | すわぷよ・ふわふわランドの舞台裏 | 事業者の「うちもやりたい」を育てる |
| 4. YourTIME・出展者紹介 | 会場の楽しみ | 出展者へのGIVE・関係構築 |
| 5. 未病ヒント | 生活の小ネタ | 世界観の信頼。効果断定はしない |

## 4. 設計原則（実証済みマーケ手法の自社翻訳）

運用中の判断基準群から本プロジェクトへ翻訳して適用する（他案件資料の原文流用はしない）。

- **フックが先。** ラベル・挨拶・自己紹介から入らない。1行目で止める。読みたい状態を作ってから誘う。
- **煽らない。** 淡々と事実と実物を見せる。「すごい」と言わせるのは文言ではなく実演。
- **CTAは受け皿が本物のときだけ。** 受け取れない「コメントで○○」を使わない（`01` §5と同一原則）。
- **体験→証明→相談の順。** 教育→販売の直列ファネルではなく、動くものを先に見せる。売り込みは相談が来てからでよい。
- **数字は自分の実績値だけ。** 架空・借り物の実績を出さない（デモデータは常にラベル表示。`01` §3と同一原則）。

## 5. ファネル全体図

```text
IG投稿
 ├ B2C: パロディ / イベント案内
 └ B2B: 裏側解説（例: 「この村、Workerとゲームエンジンでできてます」）
        │ コメント / DMキーワード（IG Harness）
        ▼
DM: 特典・案内 + source付きLINE導線
        ▼
LINE友だち追加（LINE Harness: sourceタグ）
 ├ 親子: あいさつ → すわぷよLIFF → ゲーム / 体操 / 会場
 └ 事業者: リッチメニュー「事業者の方へ」→ 事業者タグ + 案内（biz_intro_opened）
        ▼
セグメント配信（行動・流入元のみ。人の承認必須。`04_詳細設計/02` §11）
        ▼
個別相談（B2B）
```

UTAGEは使わない。IG Harness + LINE Harness + 本アプリで完結させる。

## 6. B2Bの4入口（決定-013）

| 入口 | 仕掛け | 計測 |
|---|---|---|
| 出展者レポートCTA | レポート末尾「この仕組みを自社でも → 相談してみる」（機能-309） | `biz_contact_clicked` |
| LINE事業者分岐 | リッチメニュー下段「事業者の方へ」→ 事業者タグ + 案内シナリオ | `biz_intro_opened` + Harnessタグ |
| IG直接 | 裏側解説投稿 → DMキーワード（例: 「ウラガワ」）→ B2B資料・相談導線 | IG Harnessトラッキング |
| 会場クロージング | デモ実演 → その場でレポート画面 → 後日レポートURL送付を約束 | 事業者タグ + 後日配信 |

### 会場クロージングの台本

1. 出展者に、自社ブースの当日データが映るレポート画面を見せる（デモデータの場合はラベルを明示した上で「あなたのブース版はこうなる」と示す）。
2. 「今日の来場者の動き、後日URLで送ります」→ 事業者としてLINE登録してもらう。
3. 後日、実レポート + 「同じ計測と発信の仕組みを自社でも」の1通を送る。返信で個別相談へ。

レポートが先、営業は後。GIVEの順序を崩さない。

## 7. 運用ルール

- 全自動投稿・一斉配信はしない。AI下書き → 人承認（`01` §5、業務要件の禁止事項と同一）。
- PR・提供・協力関係は明示する（ステマ規制対応）。
- B2B配信も頻度原則（週1回以下）に従い、事業者タグにだけ送る。親子セグメントへB2B文面を送らない。
- 医療・健康の効果断定はB2B文脈でもしない。
- 出展者の個別データを他の出展者・第三者への営業材料に使わない（自社事例として使う場合は本人承諾を得る）。

## 8. KPI（イベントサイクル単位）

| KPI | 位置付け |
|---|---|
| 個別相談件数 | 最重要。最終目的に直結する唯一の数字 |
| 事業者LINE登録数（会場・IG・レポート経由の内訳） | 中間指標 |
| 出展者レポートCTA率（`biz_contact_clicked` ÷ レポート閲覧） | レポートの営業力 |
| IG→LINE転換数（source別） | 入口の効率 |

数値目標はイベント初回のため設定せず、初回実績を次回の基準値にする。

## 9. 分離事項

- 投稿台本・投稿カレンダー・やすキャラの口調ガイドは別文書とする（本仕様はファネル構造のみを固定する）。
- 出展者への正式な商談資料・見積りテンプレートは本仕様の範囲外。
