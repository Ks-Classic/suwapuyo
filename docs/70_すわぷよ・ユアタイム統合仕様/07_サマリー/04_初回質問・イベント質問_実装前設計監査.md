## 2. 保存境界

| 区分 | 許可 | 禁止 |
|---|---|---|
| 家族設定 | primary_player、birth_year、birth_month、gender、派生age_band、age_as_of、ordinal | 日、氏名、学校、住所 |
| イベント回答 | survey key/version、phase、許可済み回答enum、回答時刻 | 家族プロフィールへの同行人数転記、自由記述、未許可キー |
| 計測・ログ | ステップ名、完了/スキップ、エラー種別 | pickerの年・月、DOM値、request bodyの丸ごと記録 |

DB/APIはリクエストごとのallowlistで検証する。unknown key、enum不正、欠損、本人以外の更新、冪等キー衝突のstatus codeはバックエンド規約と同時に固定する。

## 3. schema対応表

### 家族設定

| UI / local | API | DB |
|---|---|---|
| schemaVersion=3 | survey_version=`family-2026-03` | survey_responses.survey_version |
| primaryPlayer | primary_player | family_profiles.primary_player |
| children[].birthYear | children[].birth_year | family_children.birth_year |
| children[].birthMonth | children[].birth_month | family_children.birth_month |
| children[].gender | children[].gender | family_children.gender |
| server derived | response.age_band | family_children.age_band |
| 配列順 | children[].ordinal（1始まり） | family_children.ordinal |

ローカルの`children[].id`は安定描画用であり、API識別子には採用しない。送信直前に配列順から`ordinal`を1始まりで再採番する。

### イベント回答（API/DB実装前の契約候補）

| phase | survey_key | 許可回答 |
|---|---|---|
| before | event_before | attendance_plan=yes / undecided / no / unanswered |
| during | event_during | adult_count、child_count=0 / 1 / 2 / 3_plus / unanswered |
| after | event_after | attended=yes / no / unanswered |

イベント回答は`family_profiles`と`family_children`へ反映しない。`survey_responses.answers`へ許可キーだけを保存する。候補versionは`event-2026-01`だが、確認完了前にDB/API契約として固定しない。

## 6. 変更時の同期先

初回質問またはイベント質問を変更する場合、同じ変更単位で次を更新する。

1. 体験設計（ワークフロー・画面UI）
2. 基本設計（テーブル・画面一覧）
3. 詳細設計（API・シーケンス）
4. テスト計画とE2E
5. 意思決定・TODO
6. TypeScript型、validator、migration

どれか一つだけを更新した状態ではSURVEY-204を完了にしない。
