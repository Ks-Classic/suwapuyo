## 3. 実装前に回答が必要

### 要確認-001 性別の回答対象 → 決定済み（2026-07-11）

B（子どもごと）で確定。決定-016へ昇格。

### 要確認-002 アンケート完了後のキャラクター登場単位 → 決定済み（2026-07-11）

A（全キャラクター一括登場）で確定。決定-019へ昇格。

### 要確認-003 自動体操提案の間隔 → 決定済み（2026-07-11）

B（60秒）で確定。決定-017へ昇格。実機検証で違和感があれば設定値として調整する。

### 要確認-004 長期保持の具体期間 → 決定済み（2026-07-11）

無期限保持（アカウント有効な間）で確定。決定-018へ昇格。削除依頼・同意撤回・バックアップ世代失効の扱いをプライバシーポリシーへ明記する。

### 要確認-005 興味カテゴリ

出展者台帳と会場カテゴリ確定後に選択肢を固定する。自由入力は採用しない。

### 要確認-006 会場図とブース位置

正式な会場図、ブース番号、出展者ID、座標の対応表が必要。対応表がない状態で推測配置しない。

### 要確認-007 出展者・運営の認証方式（実運用移行時）

MVPは認証なしで運用する（決定-020。集計値のみ・UUIDパス・書込系API非公開が成立条件）。イベント後の実運用移行までに方式を確定する。

- A: Supabase Authのmagic link。
- B: Cloudflare Access。
- C: パスワード＋2FA。

いずれもfail-closed（未設定時は全拒否）を必須条件とする。

### 要確認-008 実装フェーズの日程確定

`07_サマリー/01`の日程（8/2逆算・仮決定）と外部Gate期日を、着手前に実稼働可能日と突き合わせて確定する。

## 4. 未確定事項の実装ルール

- `要確認`を開発者判断で確定へ変えない。
- UIデモが必要な場合は`data_mode=demo`と仮値ラベルを表示する。
- DB migration、公開文言、外部配信へ未確定値を入れない。
- 決定後は本ファイル、要件、UI、API、DB、テストを同時更新する。
