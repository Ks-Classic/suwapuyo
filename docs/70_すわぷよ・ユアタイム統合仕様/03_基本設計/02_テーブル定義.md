# テーブル定義

> 論理設計。DBスキーマ変更は別途承認後にmigrationとして実装する。主キーはUUID、日時は`timestamptz`、列挙値はcheck制約または参照表で保護する。

## 1. ID・同意

### `app_users`

| 列 | 型 | 制約・用途 |
|---|---|---|
| `id` | uuid | PK |
| `status` | text | active / blocked / deleted |
| `mode` | text | standard / demo。デモ利用者の書込は全集計から分離する |
| `first_source` | text | 正規化済み初回流入元 |
| `first_campaign_id` | uuid | campaigns FK、任意 |
| `first_seen_at` | timestamptz | 必須 |
| `last_seen_at` | timestamptz | 必須 |
| `created_at` | timestamptz | 必須 |

### `user_identities`

| 列 | 型 | 制約・用途 |
|---|---|---|
| `id` | uuid | PK |
| `user_id` | uuid | app_users FK |
| `provider` | text | line / ig_harness / line_harness |
| `subject_key` | text | HMAC等で不可逆化した照合キー |
| `linked_at` | timestamptz | 必須 |
| `unlinked_at` | timestamptz | 任意 |

`provider + subject_key`を一意にする。LINEの生user IDは保存しない。

### `consent_records`

| 列 | 型 | 制約・用途 |
|---|---|---|
| `id` | uuid | PK |
| `user_id` | uuid | app_users FK |
| `purpose` | text | product / survey / marketing 等 |
| `version` | text | 表示文面の版 |
| `status` | text | granted / withdrawn |
| `recorded_at` | timestamptz | 必須 |

## 2. 家族アンケート

### `family_profiles`

| 列 | 型 | 制約・用途 |
|---|---|---|
| `id` | uuid | PK |
| `user_id` | uuid | app_users FK、一意 |
| `primary_player` | text | child / child_and_adult / adult |
| `interest_categories` | text[] | 任意、許可カテゴリのみ |
| `updated_at` | timestamptz | 必須 |

大人・子どもの同行人数と医療・健康関係者回答は常設プロフィールへ持たない。必要なイベント時だけ、目的を示した別survey responseとして取得する。

### `family_children`

| 列 | 型 | 制約・用途 |
|---|---|---|
| `id` | uuid | PK |
| `family_profile_id` | uuid | family_profiles FK |
| `ordinal` | int | 1以上 |
| `birth_year` | smallint | 必須。許可範囲、未来年月をAPIで検証 |
| `birth_month` | smallint | 必須、1〜12 |
| `gender` | text | female / male / other / prefer_not_to_say |
| `age_band` | text | 派生値。0_2 / 3_6 / 7_9 / 10_12 / 13_plus |
| `age_as_of` | date | 年齢帯を算出した基準日 |
| `updated_at` | timestamptz | 必須 |

生まれた年・月と性別を子どもごとに継続保存する。正確な日付、氏名、学校、住所は持たない。年齢帯は年月から算出できる派生値であり、体操の表示順・説明・難易度の目安に使う。年齢・性別・行動はサービス改善と集計分析へ利用できるが、追加同意なしに個人別販促・外部突合・第三者提供へ使わず、医療的な推定を行わない（決定-031〜034）。

`family_profile_id + ordinal`を一意にする。子ども削除後のordinal再採番は表示上のみとし、既存child IDを別の子どもへ再利用しない。

### `survey_responses`

| 列 | 型 | 制約・用途 |
|---|---|---|
| `id` | uuid | PK |
| `user_id` | uuid | app_users FK |
| `survey_key` | text | family_onboarding等 |
| `survey_version` | text | 必須 |
| `answers` | jsonb | 許可キー・値をAPIで検証 |
| `completed_at` | timestamptz | 任意 |
| `created_at` | timestamptz | 必須 |

表示・集計は`family_profiles`を正とし、`survey_responses`は原本・監査・再集計用に保持する。

## 3. ゲーム・体操・キャラクター登場

### `game_sessions`

| 列 | 型 | 制約・用途 |
|---|---|---|
| `id` | uuid | PK |
| `user_id` | uuid | app_users FK |
| `started_at` | timestamptz | 必須 |
| `ended_at` | timestamptz | 任意 |
| `score` | int | 0以上 |
| `moves` | int | 0以上 |
| `mode` | text | standard / demo |

### `exercise_completions`

| 列 | 型 | 制約・用途 |
|---|---|---|
| `id` | uuid | PK、クライアント生成可能 |
| `user_id` | uuid | app_users FK |
| `exercise_type` | text | mouth / breath / neck |
| `game_session_id` | uuid | 任意 |
| `completed_at` | timestamptz | 必須 |
| `local_date_jst` | date | streak集計用 |
| `source` | text | game / home / mission |

同じ`id`の再送は200相当で同じ結果を返し、回数を増やさない。ただし既存行の`user_id`が一致しない場合は409で拒否し、他利用者の結果を返さない（冪等キーは利用者スコープ）。

### `missions`

| 列 | 型 | 制約・用途 |
|---|---|---|
| `id` | uuid | PK |
| `mission_key` | text | 一意 |
| `period_type` | text | daily / weekly / campaign |
| `condition` | jsonb | サーバー側許可schema |
| `reward` | jsonb | badge / cosmetic / content等 |
| `starts_at` | timestamptz | 必須 |
| `ends_at` | timestamptz | 必須 |

### `mission_progress`

| 列 | 型 | 制約・用途 |
|---|---|---|
| `user_id` | uuid | 複合PK |
| `mission_id` | uuid | 複合PK |
| `period_key` | text | 複合PK。`2026-07-11`（日次）、`2026-W28`（週次）等 |
| `current_value` | int | 0以上 |
| `completed_at` | timestamptz | 任意 |
| `claimed_at` | timestamptz | 任意 |

PKは`(user_id, mission_id, period_key)`とする。同一ミッション定義を期間ごとに再利用するため、`period_key`をPKへ含めない設計では日次・週次のリセットが表現できない。

### `character_arrivals`

| 列 | 型 | 制約・用途 |
|---|---|---|
| `user_id` | uuid | 複合PK |
| `character_id` | text | 複合PK |
| `arrival_reason` | text | starter / survey / artwork |
| `arrived_at` | timestamptz | 必須 |

全キャラクターはcatalog上で常時表示する。このテーブルはアンケート完了等による「村へ登場した」演出状態だけを保持し、キャラクターの存在を隠す用途には使わない。

## 4. キャンペーン・出展者・計測

### `campaigns`

`id`, `name`, `starts_at`, `ends_at`, `status`を持つ。

### `exhibitors`

`id`, `name`, `organization_name`, `category`, `booth_label`, `profile_text`, `status`, `created_at`, `updated_at`を持つ。外部URLは別テーブルまたは検証済み列へ保存する。

### `exhibitor_contents`

`id`, `exhibitor_id`, `campaign_id`, `placement`, `title`, `body`, `media_url`, `cta_label`, `cta_url`, `disclosure_label`, `status`を持つ。

追加列として`exercise_theme_tags text[]`、`map_zone_id`、`map_x`、`map_y`、`rotation_enabled`を持つ。タグは自由入力にせず運営定義の許可値から選ぶ。

### `booth_rotation_counters`

`exhibitor_content_id`, `campaign_id`, `impression_count`, `last_shown_at`, `updated_at`を持ち、`(exhibitor_content_id, campaign_id)`を一意にする。公平ローテーションの表示回数はこの表を正とし、`product_events`は監査用の生ログとして使う（利用者の直近表示除外は本人の`product_events`直近N件から判定する）。

### `product_events`

| 列 | 型 | 制約・用途 |
|---|---|---|
| `id` | uuid | PK、冪等キー |
| `user_id` | uuid | 任意、app_users FK |
| `session_id` | uuid | 任意 |
| `campaign_id` | uuid | 任意 |
| `event_name` | text | 許可リスト |
| `occurred_at` | timestamptz | 必須 |
| `properties` | jsonb | 個人情報禁止、サイズ制限 |
| `received_at` | timestamptz | 必須 |

### `report_snapshots`

`id`, `exhibitor_id`, `campaign_id`, `period_start`, `period_end`, `metrics`, `summary`, `status`, `generated_at`, `reviewed_at`を持つ。

## 5. セッション・監査

### `app_sessions`

`id_hash`, `user_id`, `expires_at`, `revoked_at`, `created_at`。cookieの生値は保存せずhashのみを保存する。

### `admin_audit_logs`

`id`, `actor_user_id`, `action`, `target_type`, `target_id`, `request_id`, `created_at`。シークレット、回答本文を含めない。

### `webhook_receipts`

`provider`, `delivery_id`, `payload_hash`, `status`, `received_at`, `processed_at`, `error_code`。`provider + delivery_id`を一意にする。

## 7. D1との分担

SupabaseへLINE HarnessやIG Harnessの全レコードを複製しない。必要な接点だけを`product_events`または`user_identities`へ連携する。

| データ | 正本 |
|---|---|
| LINE友だち・配信・会話 | LINE Harness D1 |
| IGフォロワー・DM・ゲート | IG Harness D1/R2 |
| 家族・ゲーム・体操・ミッション | Supabase |
| 出展者・レポート | Supabase |
| IGとLINEのHarness固有クロスリンク | Harness D1 |
| プロダクト利用者との明示的な紐付け | Supabase `user_identities` |
| 生LINE user ID・配信名簿・配信タグ | LINE Harness D1 |
| セグメント判定の根拠データ・判定ロジック | Supabase |
