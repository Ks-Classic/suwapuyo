# テスト計画・観点

## 1. 目的

LINE→認証→アンケート→ゲーム→体操→記録→出展者集計の縦貫通と、既存ゲーム・ふわふわランドの回帰を検証する。

## 2. テストマップ

| レベル | 対象 | 主な検証 |
|---|---|---|
| 単体 | 集計、streak、登場条件、schema | 境界値、日付、重複 |
| コンポーネント | アンケート、体操、進捗 | 状態、A11y、Reduce Motion |
| API | 認証、保存、イベント、レポート | 正常、認可、冪等、入力不正 |
| 結合 | LIFF、LINE、Supabase、Harness | token、Webhook、同期、失敗 |
| E2E | 利用者の主フロー | Write→Read→Display |
| 実機 | LINE内WebView | iOS/Android、safe area、性能 |
| 運用 | 配信・停止・復旧 | 承認、監査、トークン失効 |
| 会場実機 | タブレット→PC/スマホ→大画面 | 指描き、確認、Realtime、登場演出、回転率、回線断 |

## 3. P0結合テスト

### LINE認証

- 友だち追加済みでゲーム・記録・会場マップ・ブース紹介へ進める。
- 未友だち状態では各画面の直接URLからも利用できない。
- 未追加・ブロック中ではゲームへ進めない。
- 追加後に`getFriendship()`で再確認して進める。
- 期限切れ、偽造、別channel向けtokenを拒否する。
- LINE外ブラウザのログイン後に元の画面へ戻る。
- LINE user IDがURL、画面、console、構造化ログへ出ない。
- 同意記録（画面-018）前に利用者データが保存されない。同意文面の版が`consent_記録`へ記録される。
- セッション失効（401）後にLIFF再認証で自動復帰し、進行中のゲーム・未送信キューを失わない。

### 初回登録

- 子どもを含む場合、利用目的確認前または全児登録未完了でゲームへ進まない。
- 戻る、修正、再訪ができる。
- 誰が遊ぶかで`大人`を選んだ場合、子ども情報入力を表示しない。
- 生まれた年・月の未来値、範囲外、欠損、不正形式を拒否または未回答として安全に扱う。
- 生まれた年・月と性別がAPI・DBへ保存される一方、URL、console、構造化ログ、計測propertiesへ出ない。
- サーバー算出の`age_band`と`age_as_of`が保存年月・基準日と一致する。
- 性別の4値が表示ラベルと保存enumで正しく対応し、`prefer_not_to_say`と未入力を区別する。
- 人数先行選択、全児入力、追加・削除・戻る操作でchild IDとordinalが別人へ入れ替わらない。
- 通常時に同行者質問が出ず、開催前・当日・開催後でイベント質問が正しく切り替わる。
- 流入元、健康関係者、同行人数、遊び方が初回登録に出ない。
- 375×667 / 390×844で、60秒以内、戻る、複数児、横overflowなしをChromium E2Eで確認する。
- 画面証跡は`05_テスト/証拠/survey-*.png`へ保存し、実在個人の生まれた年・月を使用しない。
- 回答完了特典（全キャラ一括登場・決定-019）がretryで二重登場しない。
- フォーカス移動と読み上げが質問順に一致する。

### ゲーム

- 盤面スワップ、swap back、消去、重力、補充、連鎖が回帰しない。
- 375×667で盤面と主要操作が視認・操作できる。
- DOM代替操作または定義したアクセシブル操作が使える。
- 方向操作のタップ領域が基準を満たす。
- 戻る・中断後にセッションが壊れない。

### 体操・進捗

- 年齢帯別の表示順・説明・難易度がversion付き許可ルールから決まり、未監修ルールを公開しない。
- 年齢未回答時は全年齢向けの安全な既定体操を表示し、特定年齢を推定しない。
- `その子に最適`、`改善する`、`健康になる`等の禁止表現を表示しない。

- 待っているだけで完了にならず、「できた」操作で記録される。
- 一時停止、再開、スキップが動く。
- background移行時にタイマーが暴走しない。
- 同じcompletion IDを2回送っても回数は1増加。
- 機内モードで体操完了→復帰→キュー再送で1回だけ加算される（機能-208・P0）。
- 再送前にアプリを再起動しても端末キューが失われない。
- 未来の`completed_at`（+5分超）が拒否され、48時間超past分はstreakへ影響しない。
- 今日、種類別、累計、streak、missionの表示がDBと一致する。
- 日付境界はJSTで計算される。
- streakが切れても否定的表示をしない。
- 登場条件は全画面で同じ定義を参照する。
- 隠し枠やシルエットがなく、全キャラクターの姿と名前を確認できる。
- 手動起動と時間経過提案の両方で体操を開始できる。
- 自動提案の既定間隔60秒（決定-017）とスキップ後の同間隔スヌーズが機能する。
- 体操提案が盤面処理中に割り込まない。

### 出展者レポート

- 長い画面をスクロールできる。
- モバイルでKPI・表・グラフが切れない。
- デモデータを実データとして表示しない。
- レポートURLは推測不能なUUIDで、連番・列挙で他社レポートへ到達できない（MVP・決定-020）。
- 認証なし画面に個票・個人特定可能な情報が出ない（集計値のみ）。
- 書込系管理APIが本番URLで実行できない（非公開の確認）。
- （実運用移行後）出展者Aが出展者Bのデータを取得できないことを認可テストで確認する。
- 少数セルを秘匿する。
- 日付と曜日が一致する。
- グラフにテキストまたは表の代替がある。
- 「相談してみる」CTAが`biz_contact_clicked`として記録される（機能-309）。

### 会場マップ・ブース紹介

- 未友だち状態では直接URLからも開けない。
- 375×667でパン、ズーム、検索、絞り込み、選択、sheet操作ができる。
- 多数のマーカーが重なる時にクラスタまたは段階表示される。
- 選択ブースが色だけでなく輪郭、サイズ、ラベルで分かる。
- ブースsheetを閉じても地図上の文脈を失わない。
- 体操テーマ一致候補が公平ローテーションされる。
- 直近表示済みブースが連続表示されない。
- 紹介表示・詳細・CTAが別イベントとして記録される。
- アンケート回答を個人推薦へ利用しない。

### チェックイン・ブーススタンプ（デモ）

- QRを開いただけではチェックイン・訪問を確定せず、本人の確定操作後に記録する。
- 同一campaignの入口QR再読取でチェックインと限定キャラが二重付与されない。
- 同一ブースQR再読取でスタンプが二重付与されない。
- 訪問、説明、体験、購入、感想を別イベントとして保持する。
- 説明・体験・購入は自己申告として表示され、確認済み事実や売上として扱われない。
- 感想をスキップしてもスタンプと次のブース導線を失わない。
- 期限切れ・別campaign・改変token・未知boothを拒否する。
- GPS、Bluetooth、Wi-Fi権限を要求しない。
- 出展者仮レポートに個票、年月・性別と感想の組合せ、少数セルが出ない。

### 当日お絵描き・作品管理・ランド

- 3歳頃から小学生までの対象者で、色選択、指描き、戻す、消す、完成の理解と操作を確認する。
- 指の開始位置と線の開始位置が一致し、速い移動・短いタップ・画面端でも線が不自然に途切れない。
- 描画中にページスクロール、ブラウザ拡大、戻るジェスチャーが誤発火しない。
- 空作品を完成扱いしない。
- 完成作品が一度だけ確認待ちへ入り、スタッフ確認前に大画面へ出ない。
- PCとスマホの双方で同じ確認待ち作品、状態、設定版を確認できる。
- PCで登場操作した結果をスマホと大画面が反映し、スマホ操作時も同じ結果になる。
- PCとスマホから同じ作品を同時に登場操作しても一体だけ登場する。
- 非表示・保管した作品が大画面から外れ、再表示可能な状態を失わない。
- 削除・全体初期化・イベント終了は通常操作から分離され、権限確認と再確認なしに実行できない。
- 描画中にお絵描き設定を変更しても、その子の色・線幅・補助が途中で変わらず、次セッションから反映する。
- タブレット送り出しと大画面受け取りの時間・方向が連続し、子どもが自分の作品を見つけられる。
- 登場演出後、作品が通常ランドのキャラとして動き続ける。
- 音量オフでも登場完了が分かり、Reduce Motionでは大移動を抑えた代替演出になる。
- タブレット切断、表示PC切断、Supabase切断を個別に再現し、成功誤表示、作品消失、二重登場がない。
- 未送信作品を保持した状態でタブレットを再起動し、復帰・再送・スタッフ確認まで通す。
- PC・スマホ管理routeへ未認証でアクセスした場合は全書込を拒否する。認証方式未確定中は本番書込を公開しない。
- 子ども用routeから管理route、作品一覧、公開設定、同意設定へ移動できない。
- 作品画像・URL・ログへ氏名、顔、学校名等の入力を要求せず、SNS二次利用許可を会場表示許可から推定しない。
- 1人あたりの所要時間、スタッフ介入回数、描き直し率、完成率、登場までの待ち時間を実機で記録し、具体的な合格値を要確認-012で確定する。

## 4. Webhook耐性

- 署名なし・不正署名を401/403で拒否する。
- body上限超過を拒否する。
- 未知type、型不正、空IDをstrictに拒否する。
- 同じdelivery IDを並列2回送っても業務処理は1回。
- dedupeが業務処理より前に成立する。
- 4xx応答は同じ入力へ同じ結果を返す。
- 一時5xx後のretryで回復する。
- request IDとdelivery IDで入口から出口まで追跡できる。
- エラー応答にsecretや内部アカウント一覧がない。
- child timeoutがparent SLAより3秒以上短い。

2. 友だち追加Webhookが1件登録。
3. 同じWebhook再送で重複しない。

6. LIFFリンクが正しい環境を開く。
7. （P1・機能-407）名簿upsertでproduct refからタグが付与され、生LINE IDがSupabase側へ渡らない。

1. healthでトークン期限と最終Webhookを確認。
2. テストコメントまたはDMキーワードを検知。
3. 自動DMが1件だけ届く。
4. LINEリンクにsourceが付く。
5. 失効token時に成功扱いせず警告する。

## 7. 性能検証（非機能-001〜005の測定方法）

| 対象 | 測定方法 | 合格基準 |
|---|---|---|
| 非機能-001 初回表示 | Lighthouse mobile（Slow 4G相当スロットリング）＋ミッドレンジ実機（iPhone SE級 / Pixel a級） | LCP 2秒以内 |
| 非機能-002 操作応答 | DevTools Performanceでタップ→視覚反応を記録 | 100ms以内 |
| 非機能-003 ゲーム描画 | 対象実機でfps計測オーバーレイを有効化して1プレイ計測 | 30fps下限、通常60fps |
| 非機能-004 API応答 | Worker構造化ログのdurationをp95集計 | p95 1秒以内 |
| 非機能-005 画像遅延読込 | 初回表示のネットワークwaterfallでキャラ・レポート画像が読み込まれないこと | 初回リクエストに含まれない |

会場同時アクセスの想定値（仮決定: ピーク50同時セッション）で`/api/auth/line`と`/api/exercise-completions`の連続実行を確認する。
