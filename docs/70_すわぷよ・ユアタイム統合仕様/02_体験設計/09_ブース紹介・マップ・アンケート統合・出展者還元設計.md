## 0. スコープと前提Gate

**遵守するGate**

- 要確認-005: 興味カテゴリ質問は出展者台帳確定まで追加しない（自由入力不採用）→ 本設計では**来場者区分・来場人数・認知経路のみ**を扱い、興味カテゴリは扱わない。
- 要確認-011: 子どもの性別・生年月の保存境界 → 既存famliy survey（schemaVersion 3）の項目を**一切拡張しない**。家族構成の取得は既存の初回登録＋当日の人数質問で満たす。
- CHECKIN-106/107: 本番schema・署名・RLSはGate通過前に実装しない → 当面は既存のクライアント側イベント基盤（localStorage/IndexedDB、冪等append）を拡張。**将来のSupabase集計スキーマは§7に設計のみ**置き、実装しない。
- SUW-10: ブース台帳26件は全件unverified・公開不可 → ブースデータはdemo/testモードを維持し、実データ差し替え可能な構造だけ用意する。

## 1. ブースデータの一本化

現状は3系統（FeaturedBooths 3件 / village DEMO_BOOTHS / concierge 4ピン+11 POI）が並立。これを1カタログへ集約する。

- 新設 `src/booths/boothCatalog.ts`: `CatalogBooth`型 = 既存shared Booth型を拡張し、`mapPosition: {xPct,yPct} | null`、`positionsStatus: 'calibrated' | 'uncalibrated'`、`images[]`、`SNSUrl`、`prBadge`、`experiences: ('explain'|'try'|'buy')[]` を持つ。
- validator既存契約（uncalibratedはposition必須null）を維持。**ピンはcalibratedのみ描画**、uncalibratedはマップ下のリスト側に出す。位置校正が済んだブースから順にピン化できる。
- concierge側のDEMO_BOOTHS/VENUE_POISは残置（別アプリ）。MvpApp側の正はboothCatalogとする。

## 2. 会場マップ（Googleマップ・モデル）

`/village/map` を、conciergeの実証済み部品（MapViewport＝パン/ズーム/ピンチ、VenueMapSvg＝手描き会場図）をMvpApp側へ移植・共通化して本命マップにする。

**Googleマップから借りる文法**

| Googleマップ | すわぷよ版 |
|---|---|
| ピン＋カテゴリ色 | ブースピン（テーマ色、スタンプ済みは✓） |
| 下部スワイプカード | 画面下のブースカードカルーセル。スワイプ⇄ピンが双方向連動（カード送り→flyTo、ピンタップ→カード切替） |
| 検索バー | 上部検索（ブース名・カテゴリ）。ヒットでピン強調＋カード切替 |
| カテゴリチップ | 既存MAP_FILTERS踏襲（ぜんぶ/歯/こども/フード/ステージ） |
| 現在地 | GPSは使わない。**ブースQRを読んだ直後は「いまここ」ピン**を該当ブースに表示（会場内の自己位置は行動文脈から得る） |
| 経路案内 | 距離が小さいので非搭載。かわりに「つぎはここ！」＝未スタンプ最寄りブースをサジェスト |

- ピンなし状態（全ブースuncalibrated）でも成立するレイアウト: マップは会場図として意味を持ち、カードカルーセルとリストが主導線。→ 既存VillageScreens.testの「ピンなし契約」はcalibrated 0件時の挙動として維持。
- ブース詳細シートから「マップでみる」→ flyTo（calibrated時）または該当エリアへズーム（landId単位、LAND_CAMERA_TARGETS方式）。
- マップからブース詳細シートへ、詳細から`/booths`カタログへ、相互リンク。

## 4. アンケート統合（ask-once原則）

### 4.1 原則

1. **同じことは二度聞かない**: 回答済み質問は全surfaceで再表示しない。判定は新設`src/survey/surveyLedger.ts`が一元化（family survey・event survey・visitor情報を横断参照して「未回答質問セット」を返す）。
2. **1画面1質問・大ボタン**: マイクロサーベイ形式。3タップ以内/画面。
3. **事前は任意、当日はQR起点で最小必須**: 事前（自宅）はスキップ可。当日ブースQR時点で未回答の必須セットのみブロッキング（30秒以内で完了する設計）。
4. **マーケ価値の最大化**: 回答はすべて構造化キー（自由入力なし、感想コメントのみ任意自由文）。出展者レポートの集計軸（visitorType/人数/認知経路/時間帯/エンゲージメント深度）に直結させる。

### 4.2 質問インベントリ（バージョン `event-2026-02`）

| key | 質問 | 選択肢 | phase | 必須性 |
|---|---|---|---|---|
| `visitor_type` | きょうはどのお立場？ | 一般来場 / 出展者 / 出展・運営関係者 / こたえない | 共通(1回だけ) | **当日必須** |
| `adult_count` | おとなは何人で来た？ | 0/1/2/3以上 | during | **当日必須** |
| `child_count` | こどもは何人で来た？ | 0/1/2/3以上 | during | **当日必須** |
| `acquisition` | どこで知った？ | Instagram / 友だち・知り合い / 出展者から / 公式サイト / 通りがかり / その他 | 共通(1回だけ) | 任意（事前推奨） |
| `attendance_plan` | YourTIMEに行く予定は？ | 行く/迷い中/行かない | before | 任意 |
| `attended` | YourTIMEには行った？ | 行った/行かなかった | after | 任意 |

- 家族構成: 既存family survey（primaryPlayer・子ども年齢帯・性別）を正とし、**質問追加なし**。当日の実来場人数はadult_count/child_countで捕捉（family surveyとは別概念なので重複ではない）。
- 既存`event-2026-01`回答は移行不要（キー互換）。whitelistに`visitor_type`/`acquisition`を追加しsurveyVersionを`event-2026-02`へ。

### 4.3 事前アンケートの露出面（できるだけ取る）

- **すわぷよプレイ時**: ゲーム終了後（結果画面）に1問だけのマイクロサーベイカードを低頻度表示（未回答の任意質問から1つ、1日1回まで、スキップ常時可）。
- **ブース紹介閲覧時**: カタログを一定スクロール後に非モーダルの1問カード（「YourTIMEに行く予定は？」等）。閉じたら当日まで再表示しない。
- **体操完了後**: 既存ExerciseBoothIntroの下に同カードを1枚だけ。
- 事前に全必須セットが埋まっていれば、**当日はアンケートゼロでマップ直行**（最高の来場者体験）。

### 4.4 当日フロー（ブースQR起点）

```
ブースQR読取（/booths/:id/check-in または ?booth= LIFF）
  → surveyLedger.judge(): 必須セット(visitor_type, adult_count, child_count)未回答あり？
      ├─ なし → 即スタンプ演出へ
      └─ あり → 当日ミニアンケート（最大3画面、1画面1質問、戻る可、スキップ不可）→ スタンプ演出
  → スタンプ獲得（既存冪等ロジック）
  → エンゲージメント選択（複数可・後から追加可）:
      よっただけ / せつめいをきいた / たいけんした / かった / その他
  → 任意: ひとことカード（rating 4択 + 感想コメント自由文、スキップ可）
  → 完了画面: マップを見る（いまここピン付き）/ つぎのおすすめブース / スタンプ帳
```

- `BoothEngagementAction`に`'other'`を追加（既存: browsing/heard_explanation/participated/purchased）。
- イベント記録は既存の冪等append（visit 1回/ブース、engagement/feedbackは履歴累積）を踏襲。
- 入場QR（/event/:campaign/check-in）も同じ必須セット判定を通す（入場時に答えておけばブースでは聞かれない）。

## 5. 出展者還元

- 現状は`src/report/demoReports.ts`のデモデータを`ExhibitorReport`へ表示しており、実イベント集計への移行は未実装。
- 移行時は`src/report/buildReport.ts`を新設し、ローカルのcheckinイベント＋productイベントから既存`ExhibitorReport`モデル（KPI/ファネル/深度/来場者属性/時間帯/コホート）を生成する。デモと実データの種別を画面上で明示する。
- k-匿名性抑制（セル5未満は非表示）は既存`isSuppressedAggregate`を継続。
- `booth_intro_viewed`配線によりdetailViews KPIが実測化。`biz_contact_clicked`はrichペイロード（boothNo/exhibitorName）を保存するよう修正。
- 本番の集約基盤（Supabase）は§7の設計のみ。CHECKIN Gate通過後に実装。
- 出展者への提供物: 当日締め後のレポートURL（既存UUIDパス方式を踏襲、要確認-007の認証方式決定までは集計値のみ・書込なし原則を維持）。
