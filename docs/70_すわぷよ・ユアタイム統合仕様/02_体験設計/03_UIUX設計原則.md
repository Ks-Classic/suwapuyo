# UI/UX設計原則

## 1. 調査から採用する原則

Appleの現行HIGは、オンボーディングを速く、楽しく、任意にし、説明を読むより実際の操作で学ばせることを推奨している。ゲームでは44pt以上の操作領域、読みやすい文字、代替操作、進捗の保存が重要とされる。Androidは48dp以上のタップ領域、色以外の手がかり、読み上げラベルを基準とする。

本プロジェクトでは以下へ翻訳する。

- チュートリアルスライドを極力なくし、最初の一手を盤面上で案内する。
- アンケートをフォームではなく、村をつくる短い対話にする。
- モーションは状態変化の説明と達成の祝福にだけ使う。
- Reduce Motionでは移動をフェード・即時変化へ置き換える。
- 体操や音声には停止・スキップ・無音代替を用意する。

## 2. 現行アンケートの問題定義

現在の実装は、入力項目と自動前進の土台は使える一方、次の理由で完成UIとしては採用しない。

- 絵文字と汎用カードが中心で、すわぷよ固有の体験に見えない。
- 全ステップが同じ見た目で、選択の結果が世界へ反映されない。
- 質問数と進捗を前面に出し、業務フォーム感がある。
- キャラクターが案内役ではなく装飾になっている。
- 白い磨りガラス、ピル、影を重ね、情報階層が弱い。
- `かぞく / おやこ`が意味上重複し、その後の大人・子どもの人数質問とも二重になる。
- `きょうは だれといっしょ？`が来場前・自宅・開催後の利用に成立しない。
- 流入元、健康関係者、性別など、初回体験に価値を返さない質問がゲーム開始を遅らせる。

データ構造と遷移ロジックは再利用し、表示層を全面的にリメイクする。

## 3. 新しいデザイン言語「動く絵本の村」

### 画面構造

```text
背景層: 空・村・季節・遠景（edge-to-edge）
舞台層: 今の質問やゲーム盤面（主役は1つ）
案内層: キャラクターと短い吹き出し
操作層: 親指で届く下部の選択肢
状態層: 保存、通信、戻る、保護者向け詳細
```

### 色

- 主背景: 空色、芝生色、クリーム。
- 主CTA: 温かいオレンジ。
- 成功: 葉の緑。
- テキスト: 焦げ茶。純黒は使わない。
- 警告: 赤だけでなくアイコンと文言を併用。
- 1画面の強いアクセントは1色に絞る。

### 素材

- キャラクターと背景は画像資産を主役にする。
- CSSの磨りガラスは補助パネルだけに限定する。
- 絵文字はデバッグ・仮素材だけにし、最終UIは専用イラストまたはアイコンへ置換する。
- アイコンの線幅・角・塗りを統一する。

### タイポグラフィ

| 用途 | 目安 | ルール |
|---|---:|---|
| キャラの一言 | 20〜24px | 1〜2行、ひらがな中心 |
| 画面見出し | 24〜30px | 一目で目的が分かる |
| ボタン | 17〜20px | 動詞で始める |
| 保護者向け本文 | 15〜17px | 漢字可、行間1.5以上 |
| 補助情報 | 13〜15px | 重要操作には使わない |

## 4. 初回質問の新しい体験

登録値を単なるフォームではなく、これから遊ぶ人の設定として見せる。子どもの人数を先に選び、残り人数を示して全員分を最短で入力する。

```text
説明: 「みんなで遊びやすくするために」
       「年月・性別・遊んだ記録を保存します」

       ☁        [わーわー]
    ┌─────────────────┐
    │ だれが すわぷよで│
    │ 遊ぶ？            │
    └─────────────────┘

    [子ども] [子どもと大人] [大人]

子どもが遊ぶ場合:
    [1人] [2人] [3人] [4人] [5人以上]
    1人目 [生まれた年] [月] [性別]
    2人目 ...

結果:
    「3人で遊ぶ準備ができたよ」
    [いつでも変更できます]
```

生まれた年・月と性別は同意後に継続保存し、年齢帯はサーバーで算出する。進捗は`1 / 3`のように残り人数が分かる表示とし、流入元・興味・遊び方等の任意質問は初回へ混ぜない。

### 表現境界

- 採用: `年齢のめやすに合わせた、お口・からだあそびが出るよ`。
- 不採用: `その子に最適`、`症状を改善`、`健康になる`。
- 年齢帯は表示順・説明・難易度の目安にだけ使い、診断や個別の状態判定には使わない。

## 5. モーション仕様

| 用途 | 時間 | 動き |
|---|---:|---|
| タップ反応 | 80〜120ms | scale 0.98、色変化 |
| 選択確定 | 180〜240ms | 小さく着地、チェック表示 |
| 画面遷移 | 240〜360ms | 舞台の横移動またはフェード |
| キャラ登場 | 350〜550ms | spring、1回だけ |
| ミッション完了 | 600〜900ms | 星・葉を少量、短い音 |
| 重大エラー | 即時 | 揺らさず、明確な文言 |

常時浮遊、強いパララックス、大量の紙吹雪、アニメーションblurは避ける。ゲーム中の演出は盤面操作を阻害しない。

## 6. ナビゲーション

LIFF内の主ナビゲーションは3〜4項目に制限する。

```text
┌────────────────────────┐
│  あそぶ   きろく   むら  │
└────────────────────────┘
```

- 「あそぶ」: ホーム・ゲーム。
- 「きろく」: 体操、継続、ミッション。
- 「むら」: キャラクター、ブース、イベント。
- 設定・同意・データ管理は保護者メニューへ置く。

ゲーム中は主ナビゲーションを隠し、終了・体操・音だけを残す。

## 7. 画面密度

- 375×667では1画面1目的を厳守する。
- ゲーム盤面を縮めて全機能を同時表示しない。
- 追加操作はbottom sheetへ退避する。
- 下端の主要CTAはsafe area込みで固定できるが、コンテンツを覆わない。
- 長いレポートはスクロール前提とし、ゲーム画面だけを原則1画面に収める。

## 8. 文言

| 避ける | 採用する |
|---|---|
| アンケートに回答してください | 村のなかまを教えて |
| 健康スコア | できた体操 |
| 連続記録が途切れました | また今日からはじめよう |
| 未達成 | あと1こ |
| データ送信エラー | 記録を端末にあずかりました |
| 広告 | 村のブース紹介 / PR |
