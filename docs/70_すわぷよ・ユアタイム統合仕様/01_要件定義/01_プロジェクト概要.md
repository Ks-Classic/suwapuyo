# プロジェクト概要

## 1. 解決する課題

### 親子

健康・口腔育成の情報は説明されるだけでは続きにくい。子どもはゲームとして遊び、保護者は無理なく継続状況を確認できる体験を必要としている。

### イベント運営

イベントは当日の来場で接点が切れやすく、誰がどこから知り、何に興味を持ち、後日も関係が続いたかを把握しにくい。

### 出展者

出展後に得られるのが感想や来場者数だけでは、出展価値と次の改善を説明しにくい。押し売りではなく、紹介・体験・送客の接点を可視化する必要がある。

## 2. 提供価値

| 対象 | 提供価値 |
|---|---|
| 子ども | キャラクターと遊び、自然に短い体操を体験する |
| 保護者 | 回数・種類・継続を簡単に振り返る |
| 出展者 | 紹介された量、興味、体験、CTAの集計を見る |
| 運営 | LINE起点の流入・利用・会場接点を一貫して把握する |
| 制作チーム | AI・SNS・LINE・ゲーム・データをつないだ実働デモを提示する |

## 4. 成功条件

### デモ成功

- 初見の人が説明なしでもLINEからゲーム開始まで到達できる。
- アンケートが事務入力に見えず、30〜45秒以内で完了またはスキップできる。
- 1プレイ中に体操を体験し、完了直後に記録へ反映される。
- 再起動後も同じ利用者の進捗が確認できる。
- Instagramの特定投稿からLINE登録、LIFF起動までの流れを実演できる。
- 出展者向け画面で、流入・ゲーム・体操・ブース接点の意味を説明できる。

### MVP品質

- 主要導線に行き止まりがない。
- LINE外ブラウザ、未ログイン、未友だち、通信失敗を明示的に扱う。
- 390×844と375×667で主要操作が可能である。
- 重要操作のタップ領域は最低48px、子ども主操作は原則56〜72pxとする。
- `prefers-reduced-motion`、音声オフ、色以外の状態表現に対応する。

## 5. スコープ方針

MVPは「動くデモ」であり、架空の成功データを本番値として見せない。外部設定が未完了の場合はデモモードを明示する。作品QRや医院予約を削っても、LINE→ゲーム→体操→記録→紹介の価値が通ることを優先する。
