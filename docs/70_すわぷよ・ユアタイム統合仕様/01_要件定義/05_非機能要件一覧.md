# 非機能要件一覧

## 1. 性能

| ID | 要件 | MVP基準 |
|---|---|---|
| 非機能-001 | 初回表示 | LIFF起動後、低速4G相当で主要骨格を2秒以内に表示目標 |
| 非機能-002 | 操作応答 | 通常タップの視覚反応100ms以内 |
| 非機能-003 | ゲーム描画 | 対象端末で30fpsを下限、通常60fpsを目標 |
| 非機能-004 | API応答 | p95 1秒以内を目標。超過時はローディングまたは再試行を表示 |
| 非機能-005 | 画像 | 初回に不要なキャラクター・レポート画像は遅延読込 |

## 2. 可用性・耐障害性

- Cloudflare、Supabase、LINEの障害を別々に検知できる。
- 保存失敗時は「保存できた」と表示しない。
- ゲームはネットワーク瞬断で即終了しない。
-イベントはクライアント生成の一意IDで冪等に受け付ける。
- Webhookは入口重複排除、構造化ログ、strict入力検証、子処理timeoutを持つ。
- デモモードと本番モードを画面上・データ上で区別する。

## 3. セキュリティ

- LINE IDトークン・アクセストークンはサーバーで検証する。
- LINEユーザー識別子は内部IDへ変換し、画面・URL・分析propertiesへ出さない。
- Supabaseの公開スキーマはRLSを有効化する。
- サービスロール、LINEチャネルシークレット、Metaトークンをブラウザへ配布しない。
- `.env*`、トークン、実個人データをGitへ登録しない。
- 外部URLは許可プロトコルと許可ホストを検証する。
- 管理操作は監査ログへ残す。
- 書込APIはOrigin検証と`Content-Type: application/json`を必須とする（CSRF対策）。
- 利用者・IP単位のレート制限を設け、体操完了等の計上系APIはサーバー側で妥当な上限を持つ（出展者レポートの数値信頼性を守る）。

## 4. プライバシー

- 取得目的、保存期間、第三者提供、問い合わせ先を同意前に短く説明する。
- 子どもが遊ぶ場合は、取得目的の確認後に遊ぶ子ども全員の登録を完了してからゲームを開始する。個人別販促への追加同意はゲーム利用条件にしない。
- 子どもごとに生まれた年・月と性別を保存する。正確な日付、氏名、顔写真は取得しない。
- 回答は保護者アカウント単位で保持する。
- 出展者レポートは集計値のみとし、少数集計は秘匿または統合する。
- アンケート・プレイ・体操記録は無期限保持とする（アカウントが有効な間。決定-018）。削除依頼・同意撤回時は削除し、無期限保持であることと削除手段をプライバシーポリシーへ明記する。
- プロダクトデータの削除対象はSupabaseを正とする。LINE/IG Harnessはアンケート・プレイ・体操記録を保持しない。
- 生LINE user IDはLINE Harness D1のみが保持する。Supabaseのセグメント判定データと生IDを同居させない（決定-011）。
- 年齢・性別・行動は体験調整、サービス改善、集計分析に利用する。属性・行動に基づく個人別販促、外部データ突合、第三者提供は追加同意を必要とする。
- チェックイン・ブース訪問はQRと明示操作で記録し、GPS等による屋内追跡を行わない。
- 出展者レポートへ個人別データを提供せず、自己申告と確認済み事実を区別する。

## 5. アクセシビリティ

- iOSで44pt、Androidで48dpを下回る操作領域を作らない。子ども主操作は56〜72pxを基準とする。
- 本文コントラスト4.5:1、重要な非テキスト境界3:1を目標とする。
- 色だけで選択、成功、未登場を表現しない。
- `prefers-reduced-motion`で大移動、揺れ、紙吹雪を抑制する。
- 音がなくても完了・失敗が理解できる。
- 読み上げ用ラベルと論理フォーカス順を持つ。
- 時間制限がある体操にも一時停止・スキップを用意する。

## 6. 互換性

- iOS Safari / LINE内ブラウザ、Android Chrome / LINE内ブラウザを必須対象とする。
- 基準画面は375×667、390×844、430×932とする。
- PCではデモ・管理画面・出展者レポートを利用可能にする。
- Safe Areaとブラウザの動的ビューポートを考慮する。

## 7. 保守性

- React画面からLINE、Supabase、Harnessを直接呼ばず、境界モジュールを介す。
- ゲームロジック、描画、画面UI、保存を分離する。
- 1ファイル1責務とし、巨大な画面ファイルを段階的に分割する。
- TypeScriptの`any`を追加しない。
- 外部OSSはバージョンまたはコミットを固定し、更新手順とロールバックを残す。

## 8. 観測性

- すべてのAPI・Webhookにrequest IDを付与する。
- ログはイベント名、結果、duration、内部ID、エラー分類を持つ。
- トークン・回答本文・LINE識別子をログへ出さない。
- 最低限、認証成功率、友だちゲート離脱、ゲーム開始、体操完了、保存失敗を監視する。
