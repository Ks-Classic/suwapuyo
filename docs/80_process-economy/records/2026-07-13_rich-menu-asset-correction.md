ブランドキャラクターを含む生成物では、最初に利用可能素材を固定し、未指定キャラクターを生成プロンプトへ追加しない。原画保持が必要な場合は生成モデルによる再描画ではなく決定的な合成を使う。

## 追加判断候補: 開催前のLINE導線

- 主導線は`すわぷよで遊ぶ`のLIFF URIとし、LIFFログインと友だち追加確認を通してからゲームを開く。

## 統合LIFFと2種類のQRに関する設計レビュー

| 項目 | 内容 |
|---|---|
| hypothesis | 旧会場案内所LIFFを廃止し、すわぷよLIFF 1つへゲーム、作品受取、体操、ブース、マップ、スタンプを統合する。 |
| important distinction | LINEログインは利用者を同一人物として安全に識別するため、友だち追加は通知・再訪を許可してもらうための操作。友だち追加がなくてもログインによる内部利用者IDは成立するため、両者を同じ目的として説明しない。 |
| recommended entry | 作品QRをブース体験の主導線にする。利用者が描いたキャラを受け取れる具体的価値があり、ログイン・友だち追加を求める理由を理解しやすい。公式アカウントQRは、作品を作らない人、QRを失くした人、事前接点のための補助導線として併設する。 |
| access policy | 1つのLIFF IDで複数routeを持てるが、全routeを同じGateにしない。作品受取、キャラ保存、ゲーム、継続記録、スタンプはログイン必須。友だち追加をゲーム開始条件にする場合は、受け取れる価値と配信内容を先に説明する。緊急性のある基本マップは友だち追加前でも見られる候補を残す。 |
| claim security | 作品QRにLINE user IDや作品IDを直接載せず、サーバー解決するopaque・一回限り・期限付きtokenを使う。二重claim、転送、紛失、撮影失敗、オフライン、保護者端末で複数児を扱う復旧導線が必要。 |
| reporting boundary | 出展者へ個人一覧や子どもの年月・性別を渡さず、訪問・体験・継続を少数値抑制した集計で返す。YourTIME.への還元範囲はデータ取得主体、利用目的、保持、削除、第三者提供をBRAND-105で確定してから本番化する。 |
| unresolved gates | ONBOARD-303の子ども単独利用・保護者年齢境界、CHECKIN-106/107の署名・RLS、作品claimの本番schema、YourTIME.とのデータ責任、実機通信障害時の復旧。 |
| publication | private。採用案・データ責任・権利が未確定のため、公開記事へは人の確認後に要約して転用する。 |

## 2026-07-13 採用決定: LINE公式アカウントをホームにする

| 項目 | 採用内容 |
|---|---|
| home | 利用者が通常時に戻る場所はLINE公式アカウント。リッチメニューから、すわぷよ、当日マップ、出店情報、日時・アクセスへ入る。 |
| liff | 旧会場案内所LIFFを別アプリとして維持せず、`VITE_SUWAPUYO_LIFF_ID`の単一LIFFにWeb体験を統合する。機能差はLIFF IDではなくrouteで表す。 |
| normal entry | 公式アカウントの友だち追加QRを通常入口とする。ログイン画面を別サービスの入口のように見せない。 |
| artwork entry | 描いた作品のQRだけは同じLIFFの`/claim/{opaque_token}`へ直接入る。受取完了後は公式アカウントとリッチメニューの継続導線へ合流する。 |
| consent | LINEログイン、友だち追加、すわぷよの規約・プライバシー同意を目的別に説明する。友だち追加だけでデータ利用への同意を取得した扱いにしない。 |
| resilience | 通常導線はLINEへ集約するが、会場で通信障害が起きても基本案内を失わないよう、静的会場図／紙掲示のfallbackを運営設計に残す。 |
| tooling | 開催前メニュー用CLIは、画像寸法・容量・hash・LIFF IDを検証し、作成とdefault切替を分離する。下段2枠はComing Soon中にタップ領域を登録しない。本番切替には明示フラグを要求する。 |

### この過程から公開候補にできる論点

- 「ログインできること」と「戻ってきてもらえること」は別で、固定ホームをどこに置くかが体験設計を変える。
- 入口を増やすためにLIFF IDを増やす必要はなく、1つのサービス内のrouteとQRの役割で整理できる。
- リッチメニューの見た目が完成しても、未完成機能を押せる状態にすると期待を裏切る。画像上の非活性表現と実際のタップ領域を一致させる必要がある。
- 画像生成の失敗、曖昧な表示名、外部リンク未確定を隠さず、判断の変化として記録すると制作過程そのものが再利用可能な知見になる。

`publication`は引き続き`private`。会話全文、token、LIFF ID、個人情報は公開素材へ含めない。
