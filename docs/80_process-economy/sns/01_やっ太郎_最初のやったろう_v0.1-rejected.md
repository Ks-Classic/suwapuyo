## 1. この一本の目的

### 主目的

初見の人に、`すわぷよ`、`YourTIME.`、`やす太郎とやっ太郎`の関係を、説明資料ではなく一つの楽しい出来事として覚えてもらう。

### 副目的

- AIやデザインを「見栄えを作る道具」ではなく、目的を持って試し、レビューし、改善する実演として見せる。
- 出展者・事業者に、ツナやすの支援価値を押し売りせず「自分たちの企画にも、この作り方を使えるかも」と想像してもらう。
- 次の投稿・すわぷよ体験・プロフィールへ進む理由を一つだけ渡す。

### 成功の定義

最初の24〜72時間で、再生数だけでなく以下を観察する。

- コメント・返信に「すわぷよって何？」「どう作っているの？」という具体的な問いが出る。
- 保存・シェア・プロフィール遷移が、単なるいいねより相対的に取れる。
- 相談や営業の誘導ではなく、`作り方`や`目的`への反応がある。

この一本だけで受注を狙わない。受注は、認知 → 理解 → 信頼 → 会話の後に生まれる副次成果として測る。

## 2. テーマとマーケティング仮説

### 中心テーマ

**「やったろう！」は、何でも無許可でやることではない。目的を一つ決めて、戻せる最小実験を今すぐ始めること。**

### 視聴者の変化

```text
初見
  「かわいいキャラのAI投稿かな」
      ↓
物語の転換
  「YourTIME.で、遊びながら口やからだを動かすきっかけを作る“すわぷよ”の話なんだ」
      ↓
実演
  「派手な生成より、“誰に何を起こしたいか”を先に決めている」
      ↓
余韻
  「この作り方、うちの企画にも応用できそう」
      ↓
一つの行動
  次回を見る／プロフィールからすわぷよを見る
```

### 活用する実務知（公開時に固有名を前面に出さない）

`おさる式マーケ`に関する既存の内部メモからは、以下の一般化できる原則だけを採用する。

1. 入口で「誰のどんな変化か」を一瞬で分かるようにする。
2. 口約束でなく、実物・途中経過・反応で証明する。
3. 一投稿の出口は一つに絞る。
4. 先に価値と体験を出し、相談・提案・価格は後段で扱う。

出典、名称、具体的な手法の紹介をする場合は、引用可否と文脈を別途確認する。この投稿では、第三者の手法を自分たちが発明したように見せない。

## 3. 物語

やっ太郎は、YourTIME.で生まれる`すわぷよ`を知ってもらう最初の投稿を、世界一派手に作ろうとする。

胸の`とりあえずボタン`を押すと、ゲーム案、ダンス、AI動画、巨大な看板、キャラ100人分の案が一気に飛び出す。どれも見栄えはすごい。でも公式やすは笑って、ひとつだけ聞く。

> 「これを見た人に、次はどんな気分になってほしい？」

やっ太郎は一度止まり、全部を見せる代わりに、最初の一歩だけを選ぶ。

> 「すわぷよって、なんか遊んでみたい。YourTIME.って、行ってみたい。」

二人は、遊びながら口やからだを動かすきっかけを作る`すわぷよ`を、まず見せられる形にする。やっ太郎は失敗して終わるのではなく、**派手さを捨てずに目的へつなぐ方法を一つ発見する。**

## 4. 画像案：Instagramカルーセル 6枚（ASCII storyboard）

> 形式は仮説。静止画カルーセルで初回検証するが、同じ脚本をReel・Threads・Xへ同文転用しない。

### 1枚目：Hook

```text
┌──────────────────────────┐
│  [空白の大きな投稿ボード]          │
│                                      │
│      やっ太郎、最初のやったろう。    │
│                                      │
│   公式やす             やっ太郎 →   │
│  （静かにメモ）      （斜めに飛び出す）│
│                                      │
│       YourTIME. で生まれる           │
│          「すわぷよ」をつくるよ       │
└──────────────────────────┘
```

- 一目で二人の対比と、`すわぷよ`の予告を見せる。
- テキストは多くしない。`未病×エンタメ`の説明は2枚目で補う。

### 2枚目：Context

```text
┌──────────────────────────┐
│  YourTIME. は、遊びながら             │
│  元気のきっかけに出会う                │
│  未病×エンタメイベント。               │
│                                      │
│     [すーすーわーわーの世界を連想する]  │
│  雲・やわらかい村・小さな遊びの気配      │
│                                      │
│  やっ太郎「最初の投稿、世界一にする！」  │
└──────────────────────────┘
```

- 健康効果の保証はしない。
- 「遊びながら口やからだを動かすきっかけ」という表現を使用する。

### 3枚目：ぶっ飛び

```text
┌──────────────────────────┐
│       やったろう！！                    │
│                                      │
│  [とりあえずボタン] ──→               │
│   100人キャラ案 / 巨大看板 / ダンス /   │
│   宇宙サイズのゲーム画面 / AI動画案     │
│                                      │
│  やっ太郎「全部つくれば、全部伝わる！」  │
│  公式やす「……ひとつ聞いていい？」       │
└──────────────────────────┘
```

- 面白さの最大値。ここでは事故・失敗扱いにしない。
- 公式やすは叱らず、次の問いを置く。

### 4枚目：転換

```text
┌──────────────────────────┐
│  公式やす                                 │
│  「これを見た人に、次は                  │
│       どんな気分になってほしい？」        │
│                                      │
│  やっ太郎（停止 3 秒）                   │
│  しっぽ: ！ → ？ → 小さな矢印            │
│                                      │
│  [派手な案が消えるのでなく、1本の線へ]    │
└──────────────────────────┘
```

- 「目的 → 表現」の実務知を、講義ではなく会話で見せる。
- 公式やすを親・上司・説教役にしない。問いで共同作業を始める。

### 5枚目：発見

```text
┌──────────────────────────┐
│  やっ太郎                                 │
│  「すわぷよって、遊んでみたい。           │
│    YourTIME.って、行ってみたい。          │
│    そう思ってもらえたらいい！」           │
│                                      │
│  公式やす「じゃあ、最初はそこだけ作ろう」 │
│                                      │
│  [ゲームの小さな試作画面が点灯]           │
└──────────────────────────┘
```

- 派手さを否定せず、目的と接続する。
- `ゲームの小さな試作画面`は、現行アプリの実画面を使う場合、個人情報なし・未許諾素材なし・実装状態と一致するものだけにする。

### 6枚目：次の一手

```text
┌──────────────────────────┐
│  すわぷよ、つくってます。                │
│  遊びながら、口やからだを動かす          │
│  きっかけになるゲームを目指して。         │
│                                      │
│  やっ太郎「次は、ほんとに遊べるものを！」 │
│  公式やす「できたところから見せよう」     │
│                                      │
│  → 次の実験を見る                         │
└──────────────────────────┘
```

- CTAは一つだけ。初回は外部相談でなく、`次の実験を見る`またはプロフィールの`すわぷよ`導線。

| Instagram | 6枚カルーセル | 1枚目の「最初のやったろう」 | 次回を見る／プロフィールからすわぷよ |

## 6. 生成・手動レビューGate

### 生成前

- `Character Master`がまだobservedであることを制作担当へ明示する。
- 公式やすは、原画のポーズ、シャツの`Ai`、ベスト、しっぽ、顔を変えない。
- やっ太郎は、承認済みreferenceを入力に使う。未承認AI案を新しい正本にしない。
- 画像ごとにreference、prompt、model、日付、担当、用途をmanifestへ残す。

### 人のレビュー（公開前必須）

| 観点 | 確認者 | 合格条件 |
|---|---|---|
| 公式やすの原画保持 | 木幡さん | `Ai`、ポーズ、顔、衣装、しっぽが原画どおり |
| やっ太郎の同一性 | ツナマヨさん／指定監修者 | silhouette、額記号、顔、色、手足、尾、ベスト、線が許容範囲 |
| キャラクター関係 | 木幡さん | 公式やすが保護者・上司でなく、二人が対等に作用している |
| 物語・UX | 木幡さん | 初見で`YourTIME.`、`すわぷよ`、次の一手が理解できる |
| 事実・安全 | 木幡さん | 健康保証、権利誤認、未許諾素材、個人情報、実装と違う表現がない |

一つでも不合格なら公開しない。修正候補は`draft`として残し、失敗作を無断で公開素材にしない。

## 7. やっ太郎実験ノート（最小パーソナルナレッジ）

これは人格を過剰に作り込む辞典ではない。投稿・実験ごとに、やっ太郎が何を学び、次に何を変えるかを一行で蓄積する運用ノートである。

```yaml
experiment_id: YT-001
claim: 派手な表現でも、目的と次の行動が一つなら初見は迷いにくい
action: 6枚カルーセルで「ぶっ飛び → 問い → 発見」を見せる
observation: 公開後に記録。想像で埋めない
learning: 公開後に記録。成功・失敗のどちらでも次の仮説へ
next_change: 公開後に決める
canon_impact: なし。人格や造形を変える場合だけChange Requestへ
publication: review
```

「何でも知っているAI人格」を作る必要はない。蓄積するのは、**本人の体験として確認できた発見・未解決・次の仮説**だけ。これならプロセスエコノミーの素材になり、キャラの成長も本物になる。
