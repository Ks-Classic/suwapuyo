> 最終更新: 2026-06-23

> 可否判断期限: 2026-06-25

## 1. プロジェクト概要

### 1.1 プロダクト名

仮称: すーすーわーわー ふわふわランド

### 1.2 目的

子どもたちが描いた「すーすーわーわー」の塗り絵や自由イラストを撮影・アップロードし、モニター上のデジタル世界に登場させる。作品はふわふわ歩いたり、跳ねたり、漂ったりしながら、すーすーわーわーたちの世界に仲間入りする。

イベント目的は以下。

- すーすーわーわーの認知拡大。
- 子どもがAI/デジタル体験に触れる入口を作る。
- YourTIME の親子体験価値を高める。
- 口腔育成・鼻呼吸・よく噛む・姿勢などへの自然な関心を作る。
- イベント後のSNS/ショート動画/継続企画への接点を作る。

### 1.3 MVPスコープ

初期MVPでは、AI生成コメント・AI画像変換・AI動画生成は入れない。イベント当日の安定運営を最優先する。

MVPで実現すること:

- スタッフ端末で作品画像を登録できる。
- 登録作品がモニター表示画面に出現する。
- 作品が自動でふわふわ動く。
- 表示作品をランダムに入れ替えられる。
- 表示中作品を全リセットできる。
- 指定した過去作品を再表示できる。
- 不適切・失敗画像を非表示にできる。
- 通信や画面不具合時に再読み込みで復旧できる。

MVPでやらないこと:

- 子どもの顔認識。
- 個人情報取得。
- 医療診断。
- 完全自動AIキャラクター化。
- 100〜200体の常時同時表示。
- SNS自動投稿。
- 本番DBスキーマ変更。

## 3. 業務フロー

### 3.1 当日標準フロー

```txt
来場
  ↓
塗り絵/自由イラストを描く
  ↓
スタッフ撮影台へ持っていく
  ↓
スタッフが作品のみ撮影
  ↓
スタッフ画面で画像を確認
  ↓
必要ならトリミング/再撮影
  ↓
登録
  ↓
モニターに作品が登場
  ↓
子どもと保護者が見る
  ↓
必要に応じて指定再表示
```

### 3.2 混雑時フロー

```txt
作品を受付箱へ入れる
  ↓
スタッフが順番に撮影
  ↓
作品ID/受付番号を付与
  ↓
登録後、ランダム表示キューへ投入
  ↓
子どもが近くにいる場合は指定表示
```

混雑時は「登録したら必ず即表示」ではなく「ランダム出現」にする。子どもが目の前で待っている場合のみ、スタッフが指定表示する。

### 3.3 失敗時フロー

撮影失敗:

```txt
画像確認で失敗判定
  ↓
再撮影
  ↓
再撮影不可なら、作品をそのまま小さく表示するモードへ
```

表示不具合:

```txt
表示画面リロード
  ↓
作品プール復旧
  ↓
復旧しない場合はサンプル作品モードへ切替
```

通信不調:

```txt
ローカル保存モード
  ↓
スタッフ端末または表示PC単体で登録
  ↓
ネット復旧後に同期は任意
```

## 4. 機能要件一覧

### 4.1 作品登録

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---:|
| FR-001 | 画像アップロード | スタッフ端末から作品画像を登録する | Must |
| FR-002 | カメラ撮影 | ブラウザカメラで撮影する | Should |
| FR-003 | 画像確認 | 登録前にプレビューを表示する | Must |
| FR-004 | 作品ID付与 | 登録順にIDを付与する | Must |

| FR-006 | 画像削除/非表示 | 失敗画像やNG画像を非表示にする | Must |

### 4.2 画像処理

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---:|

## 5. 非機能要件一覧

### 5.1 性能

| ID | 要件 | 合格基準 |
|---|---|---|
| NFR-001 | 登録速度 | 撮影完了から表示まで60秒以内 |
| NFR-002 | 描画FPS | 表示中8〜20体で体感カクつきなし |
| NFR-003 | 連続稼働 | 6時間相当の連続稼働でクラッシュなし |
| NFR-004 | 起動時間 | 表示画面は10秒以内に復旧 |

### 5.2 表示品質

| ID | 要件 | 合格基準 |
|---|---|---|
| NFR-101 | 視認性 | 一般的なDELLモニターで自分の作品だと分かる |
| NFR-102 | 過密防止 | 同時表示が多すぎて見つけられない状態を避ける |
| NFR-103 | 色再現 | 色鉛筆/クレヨンの雰囲気を壊さない |

### 5.3 運用

| ID | 要件 | 合格基準 |
|---|---|---|
| NFR-201 | スタッフ負荷 | 1人運用でも詰まらない |
| NFR-202 | 復旧 | リロード/再起動で状態復旧できる |
| NFR-203 | オフライン余地 | ネット不調時に表示PC単体で最低限動く |

### 5.4 セキュリティ・プライバシー

| ID | 要件 | 合格基準 |
|---|---|---|
| NFR-301 | 顔写真回避 | 撮影対象は作品のみ |
| NFR-302 | 個人情報最小化 | 名前は必須にしない |
| NFR-303 | SNS転用 | イベント体験同意とSNS利用同意を分ける |
| NFR-304 | シークレット | `.env*` とAPIキーをコミットしない |

## 6. 可否判断スコープ

2026-06-25 までに判断すること:

- 白背景台紙方式で切り抜き品質が足りるか。
- PixiJS表示でイベント画面が安定するか。
- スタッフ操作が複雑すぎないか。
- モニター1台/2台で表示体験が成立するか。
- 8/2までに実装・リハーサル・素材準備が間に合うか。

2026-06-25 までに判断しないこと:

- ショート動画自動生成の最終技術選定。
- SNS投稿APIの本番連携。
- AI動画モデルの本格採用。
- 本番データベース設計。
