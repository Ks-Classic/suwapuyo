# 02-06 画面UI定義書

> 最終更新: 2026-06-23

## 1. 表示画面

### 目的

子どもが自分の作品を見つけ、すーすーわーわーの世界に仲間入りしたと感じる。

### UI構成

```txt
┌──────────────────────────────┐
│ ふわふわランド背景             │
│                              │
│  作品A      すーすー          │
│        作品B                 │
│                 わーわー      │
│       主役作品C               │
│                              │
│  作品D           作品E        │
└──────────────────────────────┘
```

### 表示ルール

- 標準12体。
- 混雑時20体まで。
- 検証上限30体。
- 主役作品は1.5〜2倍。
- 既存4キャラは作品登録後も消さず、世界観の住人として残す。
- 透過作品は前面に自然に浮かせ、非透過作品は角丸カードとして表示する。
- 作品が重なり続けないよう、移動範囲と速度を制御する。

## 2. スタッフ画面

### 目的

1人で登録・表示・復旧ができる。

### UI構成

```txt
登録
[カメラ] [画像] [描く]

カメラ
ライブカメラ
台紙認識: 探しています / そのまま止めてください / 正式判定OK / 撮り直し推奨
[撮影してプレビュー]
※ 正式判定OKが安定したら自動でプレビューへ

画像
[画像を選ぶ]

描く
[ブラシ] [色] [戻す] [消す] [プレビューへ]

プレビュー
透過: [塗り絵用紙] [白背景] [そのまま]
台紙認識: 正式判定OK / 補正なし / 透過注意
下の名前(任意)
[登録して主役表示] [登録のみ] [撮り直す]

表示操作
[全リセット] [ランダム表示] [一時停止]
同時表示数: 8 / 12 / 20 / 30

作品一覧
ART-0001 [表示] [主役] [非表示]
ART-0002 [表示] [主役] [非表示]
```

### 必須操作

- 登録して主役表示。
- 登録のみ。
- 塗り絵台紙撮影。
- 下絵入り台紙と自由描画台紙の両対応。
- デジタル描画。
- 透過モード選択。
- 正式判定OK時の自動プレビュー生成。
- 手動撮影ボタンからのプレビュー生成。
- 全リセット。
- ランダム表示。
- 指定表示。
- 非表示。
- 誤登録の削除（アーカイブ）。

### スマホUI原則

- 片手操作で主ボタンに届くよう、登録操作は画面下部に固定する。
- 撮影/画像/描くをタブで分け、同時に全部を見せない。
- 失敗時の選択肢は「撮り直す」「そのまま登録」「描くへ移動」に絞る。
- 顔写真を撮る導線に見えない文言にする。`撮影してプレビュー` の説明は「作品用紙を撮影」に寄せる。
- 手持ち撮影でも、正式判定OKなら迷わず登録できるバッジ表示にする。
- 自動で進めるのはプレビューまで。登録/表示反映はスタッフの最終タップを必須にする。
- 自動プレビュー後はライブ解析を止め、`撮り直す` でのみ再開する。
- 登録前プレビューで、顔・苗字・学校名などの確認をスタッフができる余白を確保する。
